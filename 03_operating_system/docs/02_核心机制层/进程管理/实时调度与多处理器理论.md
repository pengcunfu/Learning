# 实时调度与多处理器理论

## 6.1 实时调度理论基础

### 6.1.1 实时系统的形式化定义

**任务模型**：

实时任务 τ 可表示为四元组：τ = (C, T, D, P)

其中：
- **C**：最坏执行时间（Worst-Case Execution Time）
- **T**：任务周期（Period）
- **D**：截止时间（Deadline），通常 D ≤ T
- **P**：优先级（Priority）

**时间约束的数学表达**：

对于任务 τᵢ 的第 j 个实例：
```
Release_Time: rᵢⱼ = (j-1) × Tᵢ
Deadline: dᵢⱼ = rᵢⱼ + Dᵢ
Completion_Time: fᵢⱼ
```

**可行性约束**：
```
∀τᵢ, ∀j: fᵢⱼ ≤ dᵢⱼ
```

### 6.1.2 硬实时与软实时的形式化区分

**硬实时**（Hard Real-Time）：
```
∀task τ: P(Completion_Time ≤ Deadline) = 1
违反截止时间 → 系统失败
```

**软实时**（Soft Real-Time）：
```
∀task τ: P(Completion_Time ≤ Deadline) ≥ threshold
违反截止时间可容忍，但性能下降
```

**firm实时**：
```
∀task τ: P(Completion_Time ≤ Deadline) ≥ threshold
迟到的结果无价值，但不会导致系统失败
```

### 6.1.3 CPU利用率定理

**定义**：

系统CPU利用率 U：
```
U = Σ(i=1 to n) Cᵢ / Tᵢ
```

其中 n 为任务数量。

**理论边界**：

**刘刘刘定理**（Liu & Layland, 1973）：

对于 n 个周期任务，速率单调调度的最坏情况下界：
```
U_max(n) = n(2^(1/n) - 1)
```

**证明**：

定理：当 U > U_max(n) 时，存在不可调度的任务集

证明思路：
1. 构造临界时刻任务集
2. 分析最坏情况响应时间
3. 证明当利用率超过上界时，必定有任务错过截止时间

**上界收敛性**：
```
lim(n→∞) U_max(n) = lim(n→∞) n(2^(1/n) - 1) = ln(2) ≈ 0.693
```

**实用意义**：
```
n=2: U_max(2) = 0.828
n=3: U_max(3) = 0.779
n=4: U_max(4) = 0.756
n=10: U_max(10) = 0.717
n→∞: U_max(∞) = 0.693
```

### 6.1.4 速率单调调度（Rate Monotonic Scheduling）

**算法定义**：

优先级分配规则：
```
Priority(τᵢ) ∝ 1/Tᵢ
```
即：周期越短，优先级越高

**静态优先级**：任务优先级在运行前确定，运行中不变

**可调度性判定**：

**充分条件**（Utilization Bound Test）：
```
如果 U ≤ U_max(n)，则任务集可调度
```

**精确测试**（Response Time Analysis）：

任务 τᵢ 的最坏响应时间：
```
Rᵢ = Cᵢ + Σ(j∈hp(i)) ⌈Rᵢ/Tⱼ⌉ × Cⱼ
```
其中 hp(i) 是优先级高于 τᵢ 的任务集合

**迭代求解**：
```python
def response_time_analysis(tasks, task_id):
    """
    响应时间分析
    tasks: 任务列表 [(C₁, T₁), (C₂, T₂), ...]
    task_id: 要分析的任务索引
    """
    C_i, T_i = tasks[task_id]

    # 高优先级任务
    higher_priority = [(C, T) for idx, (C, T) in enumerate(tasks)
                       if idx < task_id]

    # 迭代求解响应时间
    R = C_i  # 初始值
    while True:
        R_new = C_i + sum((R + T_j - 1) // T_j * C_j
                          for C_j, T_j in higher_priority)

        if R_new > T_i:  # 超过周期，不可调度
            return None

        if R_new == R:  # 收敛
            return R

        R = R_new

# 示例
tasks = [(2, 5), (3, 10), (4, 20)]  # (执行时间, 周期)
for i in range(len(tasks)):
    R = response_time_analysis(tasks, i)
    if R is not None:
        print(f"任务{i}响应时间: {R}, 截止时间: {tasks[i][1]}")
    else:
        print(f"任务{i}不可调度")
```

### 6.1.5 最早截止时间优先（Earliest Deadline First）

**算法定义**：

动态优先级分配：
```
Priority(τᵢ, t) ∝ -Deadline(τᵢ, t)
```
即：截止时间越近，优先级越高

**理论基础**：

**最优性定理**（Horn, 1974）：

在抢占式单处理器系统中，EDF是最优的动态优先级调度算法：
```
如果任务集可调度，则EDF必能调度
```

**充分必要条件**：

任务集可调度当且仅当：
```
U = Σ Cᵢ/Tᵢ ≤ 1
```

**优缺点对比**：

| 特性 | RMS | EDF |
|------|-----|-----|
| 优先级类型 | 静态 | 动态 |
| 最优性 | 不保证 | 保证 |
| 实现复杂度 | 低 | 高 |
| 系统开销 | 低 | 高 |
| 可预测性 | 高 | 低 |

### 6.1.6 最短松弛时间优先（Least Laxity First）

**松弛时间**（Laxity）定义：
```
Laxity(τᵢ, t) = Deadline(τᵢ, t) - t - Remaining_Time(τᵢ, t)
```

**算法**：
```
选择 Laxity 最小的任务执行
```

**特性**：
- 也是最优算法（与EDF等价）
- 更直观，但计算开销更大

**示例2：EDF调度**

```python
def edf_simulation(tasks, simulation_time):
    """
    EDF调度模拟
    tasks: [(C, T, D)] 格式
    """
    import heapq

    # 生成任务实例
    instances = []
    for idx, (C, T, D) in enumerate(tasks):
        for j in range(simulation_time // T + 1):
            release_time = j * T
            deadline = release_time + D
            instances.append({
                'task_id': idx,
                'release': release_time,
                'deadline': deadline,
                'remaining': C
            })

    # 按发布时间排序
    instances.sort(key=lambda x: x['release'])

    time = 0
    ready_queue = []
    completed = []

    while instances or ready_queue:
        # 将已发布的任务加入就绪队列
        while instances and instances[0]['release'] <= time:
            task = instances.pop(0)
            heapq.heappush(ready_queue, (task['deadline'], task))

        if not ready_queue:
            time = instances[0]['release']
            continue

        # 选择截止时间最早的任务
        deadline, current_task = heapq.heappop(ready_queue)

        # 执行任务
        exec_time = min(current_task['remaining'],
                       instances[0]['release'] - time if instances else 1)

        current_task['remaining'] -= exec_time
        time += exec_time

        # 检查是否完成
        if current_task['remaining'] == 0:
            if time > current_task['deadline']:
                print(f"任务{current_task['task_id']}错过截止时间!")
            else:
                completed.append(current_task)

        # 如果任务未完成且新任务到达，重新加入就绪队列
        elif instances and instances[0]['release'] <= time:
            heapq.heappush(ready_queue, (current_task['deadline'], current_task))

    return len(completed)

# 示例
tasks = [(3, 8, 8), (2, 5, 5), (2, 4, 4)]
completed = edf_simulation(tasks, simulation_time=20)
print(f"完成任务数: {completed}")
```

## 6.2 多处理器调度理论

### 6.2.1 多处理器调度的复杂性

**理论困难**：

**单处理器 vs 多处理器**：

| 特性 | 单处理器 | 多处理器 |
|------|----------|----------|
| 最优算法存在 | 是（EDF、LLF） | 未知（NP难） |
| 可调度性判定 | 多项式时间 | NP完全 |
| 边界条件 | 清晰 | 不清晰 |

**复杂度类别**：

多处理器实时调度是 **NP难** 问题：
```
Partitioned_Scheduling ∈ NP-Complete
```

### 6.2.2 全局调度 vs 分区调度

#### 全局调度（Global Scheduling）

**定义**：

所有任务共享一个全局就绪队列，可迁移到任意处理器执行。

**优缺点**：
```
✓ 任务迁移灵活
✓ 负载均衡好
✗ 系统开销大
✗ 可预测性差
✗ 缓存亲和性差
```

#### 分区调度（Partitioned Scheduling）

**定义**：

任务静态分配到固定处理器，运行中不迁移。

**可归约为**：**装箱问题**（Bin Packing）

**启发式算法**：

1. **首次适应**（First Fit）：
```python
def first_fit_partitioning(tasks, m):
    """
    首次适应分区算法
    tasks: 任务列表 [(C, T)]
    m: 处理器数量
    """
    processors = [[] for _ in range(m)]
    processor_utilization = [0.0] * m

    for C, T in tasks:
        task_util = C / T

        # 查找第一个合适的处理器
        assigned = False
        for i in range(m):
            if processor_utilization[i] + task_util <= 1.0:
                processors[i].append((C, T))
                processor_utilization[i] += task_util
                assigned = True
                break

        if not assigned:
            return None  # 分区失败

    return processors
```

2. **最佳适应**（Best Fit）：
```python
def best_fit_partitioning(tasks, m):
    """
    最佳适应分区算法
    """
    processors = [[] for _ in range(m)]
    processor_utilization = [0.0] * m

    for C, T in tasks:
        task_util = C / T

        # 查找剩余空间最小的合适处理器
        best_processor = None
        min_remaining = float('inf')

        for i in range(m):
            if processor_utilization[i] + task_util <= 1.0:
                remaining = 1.0 - (processor_utilization[i] + task_util)
                if remaining < min_remaining:
                    min_remaining = remaining
                    best_processor = i

        if best_processor is None:
            return None

        processors[best_processor].append((C, T))
        processor_utilization[best_processor] += task_util

    return processors
```

3. **最差适应**（Worst Fit）：
```python
def worst_fit_partitioning(tasks, m):
    """
    最差适应分区算法
    """
    processors = [[] for _ in range(m)]
    processor_utilization = [0.0] * m

    for C, T in tasks:
        task_util = C / T

        # 查找剩余空间最大的处理器
        worst_processor = None
        max_remaining = -1

        for i in range(m):
            if processor_utilization[i] + task_util <= 1.0:
                remaining = 1.0 - (processor_utilization[i] + task_util)
                if remaining > max_remaining:
                    max_remaining = remaining
                    worst_processor = i

        if worst_processor is None:
            return None

        processors[worst_processor].append((C, T))
        processor_utilization[worst_processor] += task_util

    return processors
```

### 6.2.3 多处理器可调度性界

**充分条件**：

**Liu & Layland 界**（推广到多处理器）：

```
U ≤ m × (1 - u_max) + u_max
```
其中：
- m：处理器数量
- u_max：单个任务的最大利用率

**实例分析**：
```python
def multiprocessor_schedulability_bound(m, n):
    """
    多处理器可调度性界
    m: 处理器数量
    n: 任务数量
    """
    # 理论上界
    U_max = n * (2**(1/n) - 1)
    bound = m * (1 - U_max) + U_max

    return bound

# 示例
for m in [2, 4, 8]:
    bound = multiprocessor_schedulability_bound(m, n=10)
    print(f"{m}处理器系统上界: {bound:.3f}")
```

### 6.2.4 任务迁移开销

**迁移代价模型**：

任务 τ 从处理器 Pᵢ 迁移到 Pⱼ 的代价：
```
Cost(τ, Pᵢ→Pⱼ) = T_context_switch + T_cache_flush + T_TLB_flush
```

**总迁移开销**：
```
Total_Migration_Cost = Σ(migrations) × Cost_per_migration
```

**优化策略**：

**缓存亲和性调度**（Cache Affinity Scheduling）：

```python
def cache_aware_scheduling(tasks, m):
    """
    考虑缓存亲和性的调度
    """
    # 跟踪每个任务的缓存状态
    cache_affinity = {i: 0 for i in range(len(tasks))}

    assignments = [-1] * len(tasks)  # -1表示未分配

    for _ in range(1000):  # 模拟1000个时间单位
        # 选择任务
        for task_id in range(len(tasks)):
            # 尝试在当前处理器上执行（缓存命中）
            if assignments[task_id] != -1:
                current_processor = assignments[task_id]
                if can_execute_on(tasks[task_id], current_processor):
                    execute(tasks[task_id], current_processor)
                    cache_affinity[task_id] += 1
                    continue

            # 缓存未命中，选择迁移代价最小的处理器
            best_processor = find_best_processor(tasks[task_id], m)
            if best_processor is not None:
                if assignments[task_id] != best_processor:
                    migrate_task(task_id, best_processor)
                    cache_affinity[task_id] = 0
                assignments[task_id] = best_processor

    return assignments
```

### 6.2.5 负载均衡理论

**最优负载分配**：

设处理器 Pᵢ 的服务率为 μᵢ，负载分配为 wᵢ：

**目标**：
```
minimize max(L₁, L₂, ..., Lₘ)
subject to: Σ wᵢ = 1, wᵢ ≥ 0
```

其中 Lᵢ 是处理器 i 的负载。

**最优解**：
```
wᵢ ∝ μᵢ
```

**动态负载均衡算法**：

```python
class LoadBalancer:
    def __init__(self, m):
        self.m = m  # 处理器数量
        self.loads = [0.0] * m
        self.task_assignments = {}

    def assign_task(self, task_id, task_load):
        """选择负载最小的处理器"""
        min_load_processor = min(range(self.m),
                                key=lambda i: self.loads[i])

        self.task_assignments[task_id] = min_load_processor
        self.loads[min_load_processor] += task_load

        return min_load_processor

    def remove_task(self, task_id, task_load):
        """任务完成"""
        if task_id in self.task_assignments:
            processor = self.task_assignments[task_id]
            self.loads[processor] -= task_load
            del self.task_assignments[task_id]

    def rebalance(self):
        """重新平衡负载"""
        avg_load = sum(self.loads) / self.m

        # 识别过载和欠载处理器
        overloaded = [i for i in range(self.m) if self.loads[i] > avg_load * 1.2]
        underloaded = [i for i in range(self.m) if self.loads[i] < avg_load * 0.8]

        # 迁移任务
        for ov in overloaded:
            for un in underloaded:
                task = find_migratable_task(ov)
                if task:
                    migrate_task(task, ov, un)
```

### 6.2.6 多处理器实时调度实例

**实例：Pfair调度算法**

Pfair（Proportional Fair）是一种在多处理器上理论最优的调度算法。

**基本思想**：

将时间划分为量子，每个任务在每个时间窗口中获得与其利用率成正比的处理器时间。

**实现框架**：
```python
class PfairScheduler:
    def __init__(self, m, quantum_size):
        self.m = m  # 处理器数量
        self.quantum = quantum_size
        self.tasks = []

    def add_task(self, task_id, C, T):
        """添加任务"""
        utilization = C / T
        self.tasks.append({
            'id': task_id,
            'C': C,
            'T': T,
            'u': utilization,
            'next_deadline': 0
        })

    def schedule(self, t):
        """在时刻t调度"""
        # 计算每个任务的调度密度
        for task in self.tasks:
            task['density'] = calculate_density(task, t)

        # 选择前m个密度最高的任务
        scheduled = sorted(self.tasks,
                          key=lambda x: x['density'],
                          reverse=True)[:self.m]

        return [task['id'] for task in scheduled]

    def is_feasible(self):
        """检查可行性"""
        total_utilization = sum(task['u'] for task in self.tasks)
        return total_utilization <= self.m
```

## 6.3 能量感知调度

### 6.3.1 能量模型

**处理器功耗模型**：

```
Power = P_dynamic + P_static
P_dynamic = α × C × V² × f
P_static = I_leak × V
```

其中：
- α：活动因子
- C：负载电容
- V：电压
- f：频率
- I_leak：漏电流

**DVFS（Dynamic Voltage and Frequency Scaling）**：

通过动态调整电压和频率来降低功耗：
```
Power ∝ V² × f ∝ f³
```

### 6.3.2 能量感知调度算法

**目标**：
```
minimize Energy_Consumption
subject to: ∑ Cᵢ/Tᵢ ≤ 1
```

**算法**：
```python
def energy_aware_scheduling(tasks, voltage_levels):
    """
    能量感知调度
    tasks: 任务列表
    voltage_levels: 可用电压级别
    """
    # 为每个任务选择最低可行电压
    assignments = []

    for task in tasks:
        C, T = task['C'], task['T']
        required_utilization = C / T

        # 找到满足要求的最小电压
        for voltage, frequency in voltage_levels:
            max_util = frequency / frequency_max
            if required_utilization <= max_util:
                assignments.append({
                    'task': task,
                    'voltage': voltage,
                    'frequency': frequency,
                    'energy': calculate_energy(C, voltage, frequency)
                })
                break

    return assignments
```
