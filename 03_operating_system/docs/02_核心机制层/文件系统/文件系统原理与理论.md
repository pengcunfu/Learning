# 文件系统原理与理论

## 3.1 文件系统的本质与价值

### 3.1.1 信息的持久化抽象

文件系统解决了信息存储的根本问题：**如何在易失性存储器上实现信息的持久化**。

**理论模型**：

设存储介质为 M，文件集合为 F = {f₁, f₂, ..., fₙ}，则文件系统提供以下映射：

**存储映射**：φ_store: F × Metadata → M
**检索映射**：φ_retrieve: File_ID → F × Metadata
**更新映射**：φ_update: File_ID × Δ → F' × Metadata'

**核心性质**：
1. **持久性**（Persistence）：∀f ∈ F, P(survival(f, t > t₀)) ≈ 1
2. **原子性**（Atomicity）：φ_update 要么完全成功，要么完全失败
3. **一致性**（Consistency）：系统状态始终保持有效约束
4. **隔离性**（Isolation）：并发操作互不干扰
5. **持久性**（Durability）：已提交修改永久生效

### 3.1.2 文件系统的设计目标

**功能目标**：
```
高效存储：最大化存储空间利用率
快速访问：最小化访问延迟
数据安全：防止数据丢失和损坏
并发控制：支持多用户并发访问
```

**性能指标**：

1. **空间利用率**：
```
Space_Utilization = (User_Data_Size) / (Total_Storage_Size)
目标：≥ 90%
```

2. **访问性能**：
```
Access_Time = Seek_Time + Rotational_Latency + Transfer_Time
优化：最小化各组成部分
```

3. **可靠性**：
```
Reliability = 1 - (Data_Loss_Probability)
目标：≥ 99.999%
```

## 3.2 文件系统的理论基础

### 3.2.1 文件抽象的数学模型

**文件定义**：

文件 f 是一个三元组：f = ⟨D, M, ID⟩

其中：
- D：数据内容，D ⊆ {0,1}*（二进制串的子集）
- M：元数据，M ⊆ Metadata_Space
- ID：唯一标识符，ID ∈ Identifier_Space

**文件操作代数**：

文件系统提供的基本操作构成一个代数结构 (FS, ∘)：

- create(): ∅ → F
- read(F × Offset × Length) → Data
- write(F × Offset × Data) → F'
- delete(F) → ∅
- rename(F × New_Name) → F'

**操作公理**：
```
∀f ∈ F: create(f) ≠ ∅
∀f ∈ F: delete(create(f)) = ∅
∀f₁, f₂ ∈ F: f₁ ≠ f₂ → ID(f₁) ≠ ID(f₂)
```

### 3.2.2 目录结构的图论模型

**目录树模型**：

文件系统的目录结构形成一棵有根树 T = (V, E)，其中：

- V：节点集合，表示文件和目录
- E：边集合，表示父子关系

**性质**：
1. 有向性：(parent, child) ∈ E
2. 无环性：∄ path: v₁ → v₂ → ... → v₁
3. 单根性：∃! root: ∀v ∈ V, ∃ path: root → v

**路径表示**：

从根到文件 f 的路径：P(f) = [v₀, v₁, ..., vₙ]，其中 v₀ = root, vₙ = f

**查找算法复杂度**：

平衡树结构（如B树）：
```
时间复杂度：O(log |V|)
空间复杂度：O(|V|)
```

### 3.2.3 存储分配的优化理论

**分配策略对比**：

#### 连续分配

**模型**：每个文件占用连续的物理块

**优点**：
- 顺序访问快速：O(1) 寻址
- 实现简单

**缺点**：
- 外部碎片严重
- 文件增长受限
- 需要预知文件大小

**碎片率分析**：
```
Fragmentation_Rate = (Wasted_Space) / (Total_Space)
连续分配：Fragmentation_Rate ≈ 30-40%
```

#### 链接分配

**模型**：文件通过指针链表连接

**优点**：
- 无外部碎片
- 文件动态增长

**缺点**：
- 随机访问慢：O(n)
- 指针开销
- 可靠性问题

**访问时间分析**：
```
T_random_access = O(n) × (Block_Access_Time)
T_sequential_access = n × (Block_Access_Time)
```

#### 索引分配

**模型**：通过索引块存储文件块指针

**优点**：
- 支持随机访问：O(1)
- 动态增长
- 碎片率低

**缺点**：
- 索引块开销
- 小文件浪费空间

**性能分析**：
```
T_access = Index_Lookup_Time + Block_Access_Time
Space_Overhead = Index_Size / File_Size
小文件：Space_Overhead ≈ 25%
大文件：Space_Overhead ≈ 0.01%
```

## 3.3 文件系统的关键算法

### 3.3.1 空间管理算法

#### 位示图法（Bitmap）

**数据结构**：
```python
bitmap = [0] * (Total_Blocks // Word_Size)
# bitmap[i] = 1: block i is allocated
# bitmap[i] = 0: block i is free
```

**操作复杂度**：
```
allocate: O(n) 寻找连续0位
deallocate: O(1) 直接修改位图
空间开销: Total_Blocks / Word_Size
```

**优化技术**：
- 使用专门的硬件指令快速查找0位
- 分级位图减少搜索空间
- 缓存热门位图区域

#### 成组链接法

**思想**：将空闲块分组，用栈管理

**数据结构**：
```python
class FreeBlockGroup:
    count: int           # 本组空闲块数
    blocks: List[int]    # 空闲块编号
    next_group: int      # 下一组位置
```

**操作算法**：
```python
def allocate_block():
    if current_group.count > 0:
        return current_group.blocks.pop()
    else:
        load_next_group()
        return allocate_block()
```

**复杂度分析**：
```
allocate: O(1) 平均
deallocate: O(1)
空间开销: minimal
```

### 3.3.2 目录查找算法

#### 线性查找

```python
def find_file(name, directory):
    for entry in directory.entries:
        if entry.name == name:
            return entry
    return None
```

**复杂度**：O(n)，n为目录项数

#### 哈希表优化

```python
class DirectoryHashTable:
    def __init__(self):
        self.table = [None] * TABLE_SIZE

    def find_file(self, name):
        index = hash(name) % TABLE_SIZE
        chain = self.table[index]
        for entry in chain:
            if entry.name == name:
                return entry
        return None
```

**复杂度**：O(1) 平均，O(n) 最坏

#### B树/B+树

**现代文件系统使用**（如ext4、NTFS）

**复杂度**：
```
查找：O(log n)
插入：O(log n)
删除：O(log n)
范围查询：O(log n + k)，k为结果数量
```

### 3.3.3 一致性保证机制

#### 日志文件系统（Journaling File System）

**理论模型**：

事务T的执行过程：
```
T = {op₁, op₂, ..., opₙ}
```

**原子性保证**：

通过写前日志（WAL）：
```
1. 写日志：log(T) → stable_storage
2. 执行操作：execute(T)
3. 提交：commit(T)
```

**崩溃恢复**：
```python
def recover():
    for transaction in uncommitted_transactions:
        if transaction.is_complete():
            transaction.redo()
        else:
            transaction.undo()
```

**性能分析**：

日志开销：
```
Overhead = Log_Write_Time / Total_Write_Time
典型值：20-30%
```

可靠性提升：
```
MTTDL = MTBF / Crash_Recovery_Time
日志文件系统：MTTDL ≈ 10⁶ 小时
非日志：MTTDL ≈ 10³ 小时
```

#### 写时复制（Copy-on-Write）

**原理**：
```
修改文件时：
1. 分配新块
2. 复制旧数据
3. 修改新数据
4. 更新元数据指向新块
```

**优点**：
- 原子性保证
- 快照支持
- 崩溃一致性

**缺点**：
- 写放大
- 碎片化

**空间开销**：
```
Space_Overhead = (Modified_Data × 2) / (Total_Data)
频繁修改场景：≈ 50%
```

## 3.4 现代文件系统架构

### 3.4.1 虚拟文件系统（VFS）

**设计目标**：
- 统一接口
- 多文件系统支持
- 透明性

**架构模型**：

```
用户程序
    ↓
系统调用接口
    ↓
VFS层（抽象层）
    ↓
具体文件系统（ext4, NTFS, FAT32...）
    ↓
缓存层
    ↓
块设备驱动
```

**关键抽象**：

```c
// 超级块对象
struct super_block {
    struct file_system_type *fs_type;
    struct super_operations *s_op;
    // ...

// 索引节点对象

    struct inode_operations *i_op;
    // 文件元数据

    struct file_operations *f_op;
```

**多态性实现**：

不同的文件系统实现相同的操作接口：
```c

```

### 3.4.2 分布式文件系统

**CAP定理约束**：

在分布式文件系统中，无法同时满足：
- C：一致性（Consistency）
- A：可用性（Availability）
- P：分区容错性（Partition Tolerance）

**典型实现**：

#### GFS（Google File System）

**设计选择**：CA系统（牺牲强一致性）

**特点**：
- 单Master设计
- 大文件优化
- 自动容错
- 松散一致性

#### HDFS（Hadoop Distributed File System）

**架构**：
```
NameNode: 元数据管理
DataNode: 数据存储
Client: 访问接口
```

**数据放置策略**：
```python
def place_block(block, replication_factor=3):
    # 第一副本：本地节点
    replicas[0] = local_node

    # 第二副本：不同机架的随机节点
    replicas[1] = random_node(different_rack=True)

    # 第三副本：同机架的不同节点
    replicas[2] = random_node(same_rack=True)

    return replicas
```

**可靠性模型**：
```
Block_Reliability = 1 - (1 - Node_Reliability)^Replication_Factor
假设Node_Reliability = 99%, Replication = 3:
Block_Reliability = 1 - 0.01³ = 99.9999%
```

## 3.5 性能优化技术

### 3.5.1 缓存策略

**多级缓存架构**：

```
L1: 页缓存（Page Cache）
L2: 目录项缓存（Dentry Cache）
L3: 索引节点缓存（Inode Cache）
```

**缓存替换算法**：

LRU-K：考虑访问历史
```python
class LRU_K_Cache:
    def __init__(self, k=2):
        self.k = k
        self.history = {}  # 访问历史

    def access(self, key):
        self.history[key].append(timestamp())
        if len(self.history[key]) > self.k:
            self.history[key].pop(0)

    def evict(self):
        # 选择第k次访问时间最早的key
        return min(self.history.keys(),
                  key=lambda k: self.history[k][-self.k])
```

**缓存一致性**：

write-back策略：
```
write: 更新缓存，延迟写磁盘
read: 先查缓存，miss时读磁盘
```

write-through策略：
```
write: 同时更新缓存和磁盘
read: 只查缓存
```

**顺序预取**：

```python
def sequential_prefetch(file_offset, access_pattern):
```

## 3.6 安全性与保护

### 3.6.1 访问控制模型

**访问控制矩阵**：

```
        File1  File2  File3
User1    RW     -      R
User2    R      RW     -
User3    -      R      RW
```

**权限检查算法**：

```python
def check_permission(user, file, operation):
    # 检查用户权限
    if user in file.owner:
        return file.owner_permissions[operation]

    # 检查组权限
    if user.group in file.groups:
        return file.group_permissions[operation]

    # 检查其他权限
    return file.other_permissions[operation]
```

### 3.6.2 加密文件系统

**加密模型**：

```
Plain_File ─(Encrypt)→ Encrypted_File ─(Decrypt)→ Plain_File
```

**密钥管理**：

```python
class KeyManager:
    def __init__(self):
        self.master_key = generate_master_key()
        self.file_keys = {}

    def encrypt_file(self, file):
        file_key = generate_file_key()
        encrypted_key = encrypt(file_key, self.master_key)
        self.file_keys[file.id] = encrypted_key

        return encrypt(file.content, file_key)

    def decrypt_file(self, file):
        file_key = decrypt(self.file_keys[file.id], self.master_key)
        return decrypt(file.content, file_key)
```

**性能开销**：

```
加密开销：CPU时间增加10-20%
存储开销：密钥管理≈1-2%
访问延迟：基本无影响
```
