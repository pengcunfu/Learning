# 操作系统安全与保护理论

## 4.1 安全问题的本质与挑战

### 4.1.1 安全的信任模型

操作系统的安全性建立在**信任链**之上：

```
硬件信任根 → Bootloader → 内核 → 系统程序 → 用户程序
```

**形式化描述**：

设组件集合 C = {c₁, c₂, ..., cₙ}，信任关系 T ⊆ C × C：

**传递性**：∀c₁, c₂, c₃: ((c₁, c₂) ∈ T ∧ (c₂, c₃) ∈ T) → (c₁, c₃) ∈ T

**完整性**：∀c ∈ C: if (c, system) ∈ T then Integrity(c) = true

**安全性**：系统安全要求：
```
∀attack: P(system_resistant_to_attack) ≥ threshold
∃recovery: Recovery_Time < MTTR (Mean Time To Repair)
```

### 4.1.2 安全威胁模型

**威胁分类**：

1. **主动威胁**（Active Threats）：
   - 伪造（Spoofing）
   - 篡改（Tampering）
   - 抵赖（Repudiation）
   - 信息泄露（Information Disclosure）

2. **被动威胁**（Passive Threats）：
   - 窃听（Eavesdropping）
   - 流量分析（Traffic Analysis）

**攻击面分析**：

```
Attack_Surface = Exposed_Interfaces + Vulnerable_Components + Attack_Vectors
最小化目标：minimize(Attack_Surface)
```

### 4.1.3 CIA三元组

**信息安全三要素**：

1. **机密性**（Confidentiality）：
   ```
   ∀confidential_data d: ∀unauthorized_user u: P(u.accesses(d)) ≈ 0
   ```

2. **完整性**（Integrity）：
   ```
   ∀data d: ∀modification m: if unauthorized(m) then reject(m)
   ```

3. **可用性**（Availability）：
   ```
   ∀authorized_user u: ∀service s: P(u.accesses(s)) ≥ availability_threshold
   ```

**权衡问题**：
```
高安全性 ⟷ 低可用性
强机密性 ⟷ 高复杂度
```

## 4.2 访问控制理论

### 4.2.1 访问控制矩阵模型

**数学定义**：

设主体集合 S = {s₁, s₂, ..., sₘ}，客体集合 O = {o₁, o₂, ..., oₙ}，权限集合 R = {r₁, r₂, ..., rₖ}

访问控制矩阵 A: S × O → P(R)（P(R)是R的幂集）

**矩阵表示**：

```
        File1  File2  File3
User1    {RW}   ∅     {R}
User2    {R}    {RW}   ∅
User3    ∅      {R}    {RW}
```

**权限检查算法**：

```python
def check_access(subject, object, operation):
    # 查找访问控制矩阵
    permissions = access_matrix[subject][object]

    # 检查操作权限
    if operation in permissions:
        return True
    else:
        log_access_violation(subject, object, operation)
        return False
```

**空间复杂度**：O(|S| × |O|)

**优化策略**：
- 稀疏矩阵压缩
- 按需加载
- 缓存热点条目

### 4.2.2 能力表与访问控制列表

#### 访问控制列表（ACL）

**数据结构**：
```python
class ACL:
    def __init__(self):
        self.entries = []  # List of (subject, permissions)

    def check_permission(self, subject, operation):
        for entry in self.entries:
            if entry.subject == subject:
                return operation in entry.permissions
        return False
```

**特点**：
- 每个客体维护一个ACL
- 易于查询"谁可以访问这个对象"
- 难于查询"这个用户可以访问什么"

#### 能力表（Capability List）

**数据结构**：
```python
class Capability:
    def __init__(self, object_id, permissions, token):
        self.object_id = object_id
        self.permissions = permissions
        self.token = token  # 不可伪造的令牌

class CapabilityList:
    def __init__(self):
        self.capabilities = {}  # subject -> List[Capability]

    def check_permission(self, subject, object_id, operation):
        if subject not in self.capabilities:
            return False

        for cap in self.capabilities[subject]:
            if cap.object_id == object_id:
                return operation in cap.permissions
        return False
```

**特点**：
- 每个主体维护一个能力表
- 易于查询"这个用户可以访问什么"
- 难于撤销权限

**比较分析**：

| 特性 | ACL | 能力表 |
|------|-----|--------|
| 查询用户权限 | O(n) | O(1) |
| 查询对象访问者 | O(1) | O(n) |
| 权限撤销 | 容易 | 困难 |
| 权限委托 | 困难 | 容易 |
| 典型应用 | 文件系统 | 分布式系统 |

### 4.2.3 强制访问控制（MAC）

**Bell-LaPadula模型**（BLP模型）

**核心概念**：

安全级别 L = (Level, Categories)

- Level: {Unclassified, Confidential, Secret, Top Secret}
- Categories: {Nuclear, Military, Diplomatic, ...}

**偏序关系**：
```
L₁ ≤ L₂ ⟺ Level₁ ≤ Level₂ ∧ Categories₁ ⊆ Categories₂
```

**安全公理**：

1. **简单安全属性**（Simple Security Property）：
   ```
   subject s can read object o ⟺ Clearance(s) ≥ Classification(o)
   ```

2. **星号属性**（Star (*) Property）：
   ```
   subject s can write object o ⟺ Clearance(s) ≤ Classification(o)
   ```

3. **强星号属性**（Strong Star * Property）：
   ```
   subject s can write object o ⟺ Clearance(s) = Classification(o)
   ```

**模型验证**：

```python
def blp_check_read(subject, object):
    # 简单安全属性
    if clearnace(subject) >= classification(object):
        return True
    return False

def blp_check_write(subject, object):
    # 星号属性
    if clearnace(subject) <= classification(object):
        return True
    return False
```

**安全性证明**：

定理：BLP模型保证信息不流动安全

证明：
- 假设违反安全性，则∃s, o₁, o₂: s.read(o₁) ∧ s.write(o₂) ∧ Classification(o₁) > Classification(o₂)
- 根据简单安全属性：Clearance(s) ≥ Classification(o₁)
- 根据星号属性：Clearance(s) ≤ Classification(o₂)
- 推出：Classification(o₁) ≤ Classification(o₂)，与假设矛盾
- 证毕

#### Biba完整性模型

**关注点**：防止数据被未授权修改

**公理**：

1. **简单完整性定理**：
   ```
   subject s can write object o ⟺ Integrity_Level(s) ≥ Integrity_Level(o)
   ```

2. **完整性星号属性**：
   ```
   subject s can read object o ⟺ Integrity_Level(s) ≤ Integrity_Level(o)
   ```

**与BLP模型的对比**：

| 模型 | 关注点 | 读规则 | 写规则 |
|------|--------|--------|--------|
| BLP | 机密性 | 下读 | 上写 |
| Biba | 完整性 | 上读 | 下写 |

### 4.2.4 基于角色的访问控制（RBAC）

**核心思想**：权限与角色关联，用户与角色关联

**数学模型**：

- U: 用户集合
- R: 角色集合
- P: 权限集合
- S: 会话集合

**关系映射**：
```
UA ⊆ U × R (用户-角色分配)
PA ⊆ P × R (权限-角色分配)
session: S → U × 2^R (会话映射)
```

**RBAC约束**：

1. **职责分离**（Separation of Duties）：
   ```
   ∀r₁, r₂ ∈ R: if conflict(r₁, r₂) then
       ∀u ∈ U: ¬( (u, r₁) ∈ UA ∧ (u, r₂) ∈ UA )
   ```

2. **基数约束**（Cardinality Constraints）：
   ```
   |{u ∈ U: (u, r) ∈ UA}| ≤ Max_Users(r)
   |{r ∈ R: (u, r) ∈ UA}| ≤ Max_Roles(u)
   ```

**实现示例**：

```python
class RBACSystem:
    def __init__(self):
        self.users = {}
        self.roles = {}
        self.permissions = {}
        self.user_roles = {}      # user -> roles
        self.role_permissions = {} # role -> permissions

    def assign_role(self, user, role):
        if self.check_separation_of_duties(user, role):
            self.user_roles[user].add(role)
        else:
            raise Exception("Role assignment violates separation of duties")

    def check_permission(self, user, permission):
        user_roles = self.user_roles.get(user, set())

        for role in user_roles:
            role_perms = self.role_permissions.get(role, set())
            if permission in role_perms:
                return True
        return False
```

## 4.8 信息流控制理论

### 4.8.1 信息流的安全性定义

**基本问题**：如何防止信息从高安全级别流向低安全级别？

**形式化定义**：

设系统状态为 σ，信息流关系 ⊑：

**无干扰性质**（Noninterference）：
```
∀σ₁, σ₂: if σ₁ ≈ₗ σ₂ then after(σ₁, high_input) ≈ₗ after(σ₂, high_input)
```
其中 ≈ₗ 表示在低安全级别上不可区分。

**信息流安全格**（Security Lattice）：

定义安全格 (L, ≤)，其中：
- L：安全级别集合
- ≤：支配关系（dominance relation）

**公理**：
```
Low ≤ High  （低级别被高级别支配）
```

### 4.8.2 强制信息流控制

**格模型**（Lattice Model）：

设安全级别为格 (SC, ≤)，每个对象 o 有级别 sc(o) ∈ SC：

**允许的信息流**：
```
o₁ → o₂ ⟺ sc(o₁) ≤ sc(o₂)
```

**实例**：
```python
class SecurityLattice:
    def __init__(self):
        # 定义安全级别格
        self.levels = {
            'Unclassified': 0,
            'Confidential': 1,
            'Secret': 2,
            'TopSecret': 3
        }

    def allow_flow(self, source_level, dest_level):
        """检查信息流是否允许"""
        return self.levels[source_level] <= self.levels[dest_level]

    def enforce_flow(self, source, dest, source_level, dest_level):
        """强制执行信息流控制"""
        if not self.allow_flow(source_level, dest_level):
            raise SecurityException(
                f"禁止信息流: {source}({source_level}) → {dest}({dest_level})"
            )
        # 执行信息传输
        transfer_data(source, dest)
```

**复合安全级别**：
```
SC = Level × PowerSet(Categories)

sc₁ ≤ sc₂ ⟺ level₁ ≤ level₂ ∧ categories₁ ⊆ categories₂
```

### 4.8.3 隐蔽通道分析

**定义**：未设计用于通信的通道，可用于违反安全策略

**分类**：

1. **存储隐蔽通道**（Storage Channels）：
   - 共享资源的状态变化
   - 文件锁、磁盘空间等

2. **时间隐蔽通道**（Timing Channels）：
   - 操作时序的变化
   - CPU调度、资源竞争等

**隐蔽通道容量计算**：

**无噪通道容量**（Shannon容量）：
```
C = max_p(X) I(X; Y) = max_p(X) [H(Y) - H(Y|X)]
```
其中：
- I(X; Y)：互信息
- H(Y)：输出熵
- H(Y|X)：条件熵

**实例分析**：
```python
def covert_channel_capacity(transitions, symbol_times):
    """
    计算隐蔽通道容量
    transitions: 状态转移序列
    symbol_times: 符号持续时间
    """
    # 估计转移概率矩阵
    P = estimate_transition_matrix(transitions)

    # 计算平稳分布
    pi = compute_stationary_distribution(P)

    # 计算信道容量
    capacity = 0
    for i, p_i in enumerate(pi):
        row_sum = 0
        for j, p_ij in enumerate(P[i]):
            if p_ij > 0:
                row_sum -= p_ij * log2(p_ij)
        capacity += p_i * row_sum

    # 考虑符号持续时间
    symbol_rate = 1.0 / mean(symbol_times)

    return capacity * symbol_rate  # bits/second

# 示例：文件锁隐蔽通道
transitions = [0, 1, 0, 1, 0, 1, ...]  # 锁定/解锁序列
capacity = covert_channel_capacity(transitions, symbol_times=[0.001, 0.001])
print(f"隐蔽通道容量: {capacity:.2f} bits/s")
```

**隐蔽通道消减**：

### 4.8.4 旁路攻击

**原理**：通过系统实现的侧信道泄露信息

**常见类型**：

```python
    return result == 0
```

## 4.9 安全内核理论与形式化验证

### 4.9.1 引用监控机

**定义**（Ref: Anderson, 1972）：

引用监控机（Reference Monitor）是负责执行访问控制的概念性抽象机。

**必须满足三个性质**：

1. **必须被仲裁**（Mediated）：
   ```
   ∀access_to_object: access_must_pass_through_reference_monitor
   ```

2. **防篡改**（Tamper-Proof）：
   ```
   ∄attack: attacker_can_modify_reference_monitor
   ```

3. **足够小以验证**（Small Enough to Verify）：
   ```
   Complexity(RM) ≤ Threshold_Verifiable
   ```

**实现**：引用监控机的实现称为引用监控机制（Reference Validation Mechanism）

### 4.9.2 安全内核架构

**定义**：操作系统中负责实施安全策略的硬件和软件集合

**设计原则**：

1. **最小权限**（Least Privilege）：
```
每个组件只拥有完成任务所需的最小权限
```

2. **完全仲裁**（Complete Mediation）：
```
所有访问都必须经过检查，无一例外
```

3. **开放设计**（Open Design）：
```
安全不应依赖于机制的秘密性
```

**安全内核实现**：
```c
// 安全内核的系统调用处理框架
void secure_kernel_syscall_handler(int syscall_num, void* args) {
```

**模型检验**（Model Checking）：

```python
class ModelChecker:
    def __init__(self, model, spec):
        self.model = model  # Kripke结构
        self.spec = spec    # CTL/LTL公式

    def verify(self):
        """模型检验算法"""
        states = self.model.get_states()
        visited = set()

        for state in states:
            if state not in visited:
                if not self.check_state(state, visited):
                    return CounterExample(state)

        return True

    def check_state(self, state, visited):
        """检查单个状态"""
        visited.add(state)

        # 检查当前状态是否满足规范
        if not self.spec.holds_in(state):
            return False

        # 递归检查后继状态
        for successor in self.model.successors(state):
            if successor not in visited:
                if not self.check_state(successor, visited):
                    return False

        return True
```

### 4.9.4 信息流分析的类型系统

**安全类型系统**（Security Type System）：

```python
class SecurityType:
    def __init__(self, security_level):
        self.level = security_level

class TypedExpression:
    def __init__(self, expr, type):
        self.expr = expr
        self.type = type

class SecurityTypeChecker:
    def __init__(self):
        self.env = {}  # 变量到类型的映射

    def check_expression(self, expr):
        """检查表达式的类型安全性"""
        if isinstance(expr, Variable):
            return self.env[expr.name]

        elif isinstance(expr, BinOp):
            left_type = self.check_expression(expr.left)
            right_type = self.check_expression(expr.right)

            # 信息流检查
            if not self.allow_flow(left_type, right_type):
                raise SecurityError(
                    f"禁止信息流: {left_type.level} → {right_type.level}"
                )

            return join_security_level(left_type, right_type)

        elif isinstance(expr, Assignment):
            value_type = self.check_expression(expr.value)
            var_type = self.env.get(expr.variable)

            if var_type is None:
                self.env[expr.variable] = value_type
            else:
                if not self.allow_flow(value_type, var_type):
                    raise SecurityError(
                        f"禁止赋值: {value_type.level} → {var_type.level}"
                    )

            return value_type

    def allow_flow(self, source_type, dest_type):
        """检查信息流是否允许"""
        return source_type.level <= dest_type.level
```

### 4.11.2 远程认证

**协议流程**：

```
1. Challenger → Attestor: nonce (challenge)
2. Attestor → TPM: Quote(nonce, PCR_values)
3. TPM → Attestor: Quote(PCR_values) || Signature
4. Attestor → Challenger: Quote || PCR_values || Signature || AIK_cert
5. Challenger: Verify(Signature) && Check(PCR_values)
6. Challenger → Attestor: Result
```

**实现示例**：
```python
class RemoteAttestation:
    def __init__(self, tpm):
        self.tpm = tpm
        self.aik_key = None  # Attestation Identity Key

    def generate_aik(self):
        """生成认证身份密钥"""
        self.aik_key = self.tpm.generate_key(
            key_type="RSA",
            key_usage="Attestation"
        )

        # CA签名AIK证书
        cert = self.tpm certify_key(self.aik_key, CA_key)
        return cert

    def attest_system(self, pcr_indices, nonce):
        """证明系统状态"""
        # 1. 测量系统状态
        measurements = self.measure_system()
        for pcr_index, measurement in measurements.items():
            self.tpm.extend_pcr(pcr_index, measurement)

        # 2. 生成Quote
        quote = self.tpm.quote(pcr_indices, nonce)

        # 3. 构造证明包
        attestation_package = {
            'quote': quote,
            'pcr_values': [self.tpm.pcr_values[i] for i in pcr_indices],
            'aik_cert': self.aik_key.certificate,
            'nonce': nonce
        }

        return attestation_package

    def verify_attestation(self, attestation_package):
        """验证证明"""
        # 1. 验证AIK证书
        if not verify_certificate(attestation_package['aik_cert']):
            return False

        # 2. 验证Quote签名
        if not self.tpm.verify_quote(
            attestation_package['quote'],
            attestation_package['pcr_values'],
            attestation_package['nonce'],
            attestation_package['aik_cert'].public_key
        ):
            return False

        # 3. 检查PCR值是否符合预期
        expected_pcrs = self.get_expected_pcr_values()
        for i, pcr_value in enumerate(attestation_package['pcr_values']):
            if pcr_value != expected_pcrs[i]:
                return False

        return True
```

## 4.12 微内核安全架构

### 4.12.1 能力系统

**能力**（Capability）的定义：

**形式化定义**：

```
Capability = ⟨Object_ID, Permissions, Token⟩
```

其中：

- Permissions：授权的操作集合
- Token：不可伪造的证明（签名、加密等）

**权限撤销**：
```c
// 撤销对文件的能力
void revoke_file_access(Capability* file_cap) {
    // 1. 从能力空间移除
    cspace_delete(file_cap);

    // 2. 通知对象管理器
    send_revoke_message(file_cap->object_id);

    // 3. 清理相关资源
    cleanup_object_resources(file_cap->object_id);
}
```

## 4.13 总结

操作系统安全理论与技术构成了一个多层次的防御体系：

### 理论基础层
- **信息流控制**：防止数据泄露的数学模型
- **访问控制**：DAC、MAC、RBAC等形式化模型
- **隔离性理论**：沙箱、虚拟化的隔离度分析

### 机制实现层
- **安全内核**：引用监控机的实现
- **内存安全**：栈保护、ASLR、DEP、CFG
- **可信计算**：TPM、远程认证、度量启动

### 高级应用层
- **微内核安全**：能力系统、消息传递安全
- **形式化验证**：模型检验、定理证明
- **隐蔽通道分析**：容量计算、带宽限制

### 核心原则
1. **纵深防御**：多层安全控制
2. **最小权限**：最小化访问权限
3. **完全仲裁**：所有访问都受检查
4. **开放设计**：不依赖秘密性
5. **安全默认值**：默认安全配置

操作系统安全是一个不断发展的领域，需要在安全性、可用性和性能之间持续平衡。理解这些理论和技术，对于设计和实现安全的操作系统至关重要。
