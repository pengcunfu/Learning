# Trie树（字典树、前缀树）

## 一、Trie树的基本概念

### 1.1 什么是Trie树？

**Trie树**（发音为"try"），也称为**字典树**或**前缀树**，是一种专门用于处理字符串的树形数据结构。

**核心思想：**
> 利用字符串之间的公共前缀，将字符串集合存储在一棵树上

**名称由来：**
- **Trie**：取自**Retrieval**（检索）的中间部分
- 也被称为**前缀树**（Prefix Tree）
- 中文常称为**字典树**（Dictionary Tree）

### 1.2 Trie树的特点

**特点1：字符串专用**
- 专门设计用于字符串处理
- 每个节点代表一个字符
- 路径代表字符串

**特点2：前缀共享**
- 公共前缀只存储一次
- 节省存储空间
- 高效的前缀匹配

**特点3：根节点为空**
- 根节点不包含字符
- 只是一个入口点

**特点4：单词结束标记**
- 需要标记单词的结束
- 通常用布尔字段或特殊字符表示

### 1.3 Trie树的结构示意

**存储单词：apple, app, apply, banana**

```
          (root)
          /    |        \
         a     b        ...
        / \     \
       p   p*    a
      /     \     \
     p       p    n
    /         \     \
   l*         l*    a
  /                 \
  e                  *
```
*号表示单词结束

**路径对应的字符串：**
- a-p-p-l-e → apple
- a-p-p → app
- a-p-p-l-y → apply
- b-a-n-a-n-a → banana

### 1.4 Trie树 vs 其他结构

| 特性 | Trie树 | 哈希表 | 平衡树 |
|------|--------|-------|--------|
| 查找 | O(m) | O(1) | O(m log n) |
| 插入 | O(m) | O(1) | O(m log n) |
| 空间 | 大 | 小 | 中等 |
| 前缀查找 | 支持 | 不支持 | 困难 |
| 有序遍历 | 支持 | 不支持 | 支持 |

*m为字符串长度

## 二、Trie树的基本操作

### 2.1 插入操作

**插入思路：**
```
1. 从根节点开始
2. 对于字符串中的每个字符：
   a. 检查字符对应的子节点是否存在
   b. 若存在，移动到该子节点
   c. 若不存在，创建新子节点
3. 在最后一个字符节点标记单词结束
```

**示例：插入"cat"**
```
初始：
(root)

插入'c'：
(root)
  |
  c

插入'a'：
(root)
  |
  c
  |
  a

插入't'：
(root)
  |
  c
  |
  a
  |
  t  ← 标记单词结束
```

**时间复杂度：** O(m)，m为字符串长度

### 2.2 查找操作

**查找思路：**
```
1. 从根节点开始
2. 对于字符串中的每个字符：
   a. 检查字符对应的子节点是否存在
   b. 若不存在，返回未找到
   c. 若存在，移动到该子节点
3. 到达字符串末尾时：
   a. 检查是否有单词结束标记
   b. 有标记则找到，否则未找到
```

**示例：查找"cat"**
```
(root)
  |
  c
  |
  a
  |
  t* ← 有标记，找到！
```

**时间复杂度：** O(m)

### 2.3 删除操作

**删除思路：**
```
1. 先查找单词是否存在
2. 如果不存在，直接返回
3. 如果存在：
   a. 清除单词结束标记
   b. 如果该节点没有其他子节点
   c. 递归删除无用的节点
   d. 直到到达有子节点的节点或根节点
```

**关键点：**
- 不能删除其他单词的前缀节点
- 需要检查节点是否被其他单词使用

**示例：删除"cat"**
```
删除前：
(root)
  |
  c
  |
  a
  |
  t* ← 清除标记，检查是否可以删除
      (假设c-a-t路径只有"cat"使用)

删除后：
(root)
(整个c-a-t路径都被删除)
```

**时间复杂度：** O(m)

### 2.4 前缀查找

**查找前缀思路：**
```
与前缀查找类似，但不需要单词结束标记
只要能完整遍历完前缀字符串即可
```

**应用：**
- 自动补全
- 拼写检查
- IP路由最长前缀匹配

## 三、Trie树的优化

### 3.1 压缩Trie（Compressed Trie）

**问题：**
- 单路径节点浪费空间
- 例如：a-b-c-d-e的长链

**解决方案：**
- 将单路径节点合并
- 节点存储字符串而非单个字符

**压缩前：**
```
(root)
  |
  a
  |
  b
  |
  c
```

**压缩后：**
```
(root)
  |
  abc
```

### 3.2 后缀Trie（Suffix Trie）

**应用：**
- 字符串匹配
- 子串查找
- 基因序列分析

### 3.3 三叉Trie（Ternary Search Trie）

**特点：**
- 每个节点有三个子节点：左、中、右
- 左：小于当前字符
- 中：等于当前字符
- 右：大于当前字符

**优势：**
- 空间效率更高
- 可以保持字符串有序
- 类似二叉搜索树

## 四、Trie树的应用

### 4.1 自动补全

**应用场景：**
- 搜索引擎的搜索建议
- IDE的代码补全
- 输入法的联想输入

**实现思路：**
```
1. 将常用词构建为Trie树
2. 用户输入前缀时：
   a. 在Trie树中查找前缀
   b. 收集该节点下的所有单词
   c. 返回建议列表
```

**性能优势：**
- 前缀匹配高效
- 只需要遍历前缀长度的路径
- 比逐个比较快得多

### 4.2 拼写检查

**应用场景：**
- 文档编辑器的拼写检查
- 搜索引擎的拼写纠错
- 编程语言的语法检查

**实现思路：**
```
1. 将词典构建为Trie树
2. 对于每个单词：
   a. 在Trie树中查找
   b. 未找到则拼写错误
   c. 可提供相似词建议
```

### 4.3 IP路由

**最长前缀匹配：**
```
路由表：
192.168.0.0/16 → 网关A
192.168.1.0/24 → 网关B
192.168.1.1/32 → 主机C

对于IP 192.168.1.100：
匹配最长前缀 192.168.1.0/24
选择网关B
```

**Trie树实现：**
- 将IP地址的二进制位构建Trie树
- 查找最长匹配前缀
- 高效的路由查找

### 4.4 单词统计

**应用：**
- 文档词频统计
- 搜索引擎的关键词频率
- 文本分析

**实现思路：**
```
在Trie节点中维护计数器：
1. 每次插入时增加计数
2. 可以快速获取词频
3. 支持前缀词频统计
```

### 4.5 游戏应用

**单词搜索游戏：**
- 检查单词是否在词典中
- 快速的前缀检查
- 生成有效单词列表

**Boggle类游戏：**
- 字母网格
- 找出所有可能的单词
- Trie树快速验证

## 五、Trie树的优缺点

### 5.1 优点

1. **前缀查找高效**
   - 天然支持前缀匹配
   - O(m)时间复杂度
   - 哈希表无法高效实现

2. **字符串操作高效**
   - 插入、查找都是O(m)
   - m为字符串长度，通常较小
   - 不需要计算哈希值

3. **按字典序遍历**
   - 中序遍历得到有序字符串
   - 支持范围查询

4. **空间利用（有时）**
   - 公共前缀只存储一次
   - 对于相似字符串集合，空间效率高

5. **实现简单**
   - 递归定义，易于理解
   - 插入查找逻辑简单

### 5.2 缺点

1. **空间开销大**
   - 每个字符都需要节点
   - 指针占用大量空间
   - 稀疏数据浪费空间

2. **只适合字符串**
   - 专门用于字符串
   - 不适用于其他类型

3. **内存不连续**
   - 节点分散分配
   - 缓存性能差
   - 访问速度慢

4. **实现复杂度**
   - 动态内存分配
   - 需要手动管理内存
   - 容易出错

### 5.3 与哈希表对比

| 特性 | Trie树 | 哈希表 |
|------|--------|-------|
| 查找 | O(m) | O(1)* |
| 插入 | O(m) | O(1)* |
| 前缀查找 | 支持 | 困难 |
| 空间 | 通常较大 | 较小 |
| 字符串操作 | 优化 | 通用 |
| 实现复杂度 | 中等 | 简单 |

*平均情况

## 六、Trie树的实现考虑

### 6.1 节点结构设计

**基本节点：**
```
struct TrieNode {
    bool is_end;              // 单词结束标记
    TrieNode* children[26];   // 26个字母（小写）
}
```

**优化节点：**
```
struct TrieNode {
    bool is_end;
    map<char, TrieNode*> children;  // 动态字符集
    int count;                       // 词频统计
}
```

### 6.2 内存管理

**问题：**
- 大量小对象分配
- 内存碎片化
- 性能开销

**解决方案：**
- 对象池技术
- 内存池分配
- 数组批量分配

### 6.3 字符集处理

**ASCII字符集：**
- 128个字符
- 直接数组索引

**Unicode字符集：**
- 字符数量巨大
- 使用map存储子节点

**混合策略：**
- 常用字符用数组
- 其他字符用map

## 七、Trie树的变种

### 7.1 Radix Tree（基数树）

**特点：**
- 压缩单路径节点
- 每个节点存储多个字符
- 空间效率更高

**应用：**
- Linux内核的进程地址管理
- 文件系统路径管理

### 7.2 Suffix Tree（后缀树）

**定义：**
- 存储字符串的所有后缀
- 支持复杂的字符串操作

**应用：**
- 基因序列分析
- 全文索引
- 字符串匹配

### 7.3 Suffix Array（后缀数组）

**特点：**
- 比后缀树节省空间
- 仍支持复杂的字符串操作
- 与后缀树功能相当

**应用：**
- 基因序列比对
- 数据压缩
- 文本检索

### 7.4 AC自动机

**定义：**
- Trie树 + KMP算法
- 同时匹配多个模式串

**应用：**
- 多模式字符串匹配
- 入侵检测系统
- 病毒扫描

## 九、性能优化

### 9.1 空间优化

**压缩Trie：**
- 合并单路径节点
- 节省大量空间

**Lazy创建：**
- 只在需要时创建节点
- 避免预分配

**内存池：**
- 批量分配节点
- 减少分配开销

### 9.2 时间优化

**缓存：**
- 缓存常用查询
- 提高响应速度

**并行处理：**
- 并行构建Trie树
- 并行查询

**SIMD优化：**
- 批量字符比较
- 硬件加速

### 9.3 混合结构

**Trie + 哈希表：**
- 浅层节点用Trie
- 深层节点用哈希表

**Trie + 数组：**
- 前缀用Trie
- 后缀用数组索引
