# 树（Tree）数据结构

## 一、树的基本概念

### 1.1 定义

**树**是一种抽象数据类型（ADT）或是实现这种抽象数据类型的数据结构，用来模拟具有树状结构性质的数据集合。它是由n（n≥1）个有限节点组成一个具有层次关系的集合。

**核心特征：**
- 有且仅有一个特定的称为根（Root）的节点
- 其余节点可分为m（m≥0）个互不相交的有限集合T₁、T₂、...、Tm，其中每一个集合本身又是一棵树，称为根的子树（SubTree）

### 1.2 基本术语

| 术语 | 定义 |
|------|------|
| **节点（Node）** | 树的基本单元，包含数据元素和若干指向子树的分支 |
| **根节点（Root）** | 树中唯一没有前驱的节点，是树的顶层节点 |
| **父节点（Parent）** | 若一个节点含有子节点，则该节点称为其子节点的父节点 |
| **子节点（Child）** | 一个节点含有的子树的根节点称为该节点的子节点 |
| **兄弟节点（Sibling）** | 拥有相同父节点的节点互称为兄弟节点 |
| **叶子节点（Leaf）** | 没有子节点的节点，也称为终端节点 |
| **分支节点** | 度不为0的节点，也称为非终端节点 |
| **节点的度（Degree）** | 节点拥有的子树个数 |
| **树的度** | 树内各节点度的最大值 |
| **节点的层次（Level）** | 从根节点开始，根为第1层，根的子节点为第2层，以此类推 |
| **树的深度（Depth）** | 树中节点的最大层次数 |
| **树的高度（Height）** | 从根节点到最远叶子节点的最长路径上的边数 |
| **有序树** | 树中节点的各子树看成是有次序的，不能互换 |
| **无序树** | 树中节点的各子树看成是无次序的，可以互换 |
| **森林（Forest）** | m（m≥0）棵互不相交的树的集合 |

### 1.3 树的表示方法

#### 1.3.1 图示表示法
使用倒置的树状图形，根在上，叶子在下

#### 1.3.2 嵌套集合表示法
用集合的包含关系来表示树的结构

#### 1.3.3 广义表表示法
将树表示为根和子树森林的广义表

#### 1.3.4 凹入表示法
通过缩进和连线表示层次关系

## 二、二叉树（Binary Tree）

### 2.1 二叉树的定义

**二叉树**是每个节点最多有两个子树的树结构。通常子树被称作"左子树"（Left Subtree）和"右子树"（Right Subtree）。

**重要性质：**
- 第i层最多有2^(i-1)个节点
- 深度为k的二叉树最多有2^k-1个节点
- 对于任何一棵二叉树，如果其终端节点数为n₀，度为2的节点数为n₂，则n₀ = n₂ + 1

### 2.2 二叉树的分类

#### 2.2.1 满二叉树（Full Binary Tree）
**定义：** 所有非叶子节点都有两个子节点，且所有叶子节点都在同一层

**特点：**
- 第i层有2^(i-1)个节点
- 深度为k的满二叉树有2^k-1个节点
- 可以对节点进行连续编号

#### 2.2.2 完全二叉树（Complete Binary Tree）
**定义：** 除最底层外，每一层都被完全填充，并且最底层的节点尽可能靠左排列

**特点：**
- 具有n个节点的完全二叉树深度为⌊log₂n⌋+1
- 可以用数组高效存储
- 适合实现堆结构

#### 2.2.3 平衡二叉树（Balanced Binary Tree）
**定义：** 任意节点的两个子树的高度差不超过1

**特点：**
- 保证查找、插入、删除操作的时间复杂度为O(log n)
- 避免树退化为链表

### 2.3 二叉树的遍历方式

#### 2.3.1 深度优先遍历（DFS）

**前序遍历（Preorder Traversal）**
- 顺序：根节点 → 左子树 → 右子树
- 应用场景：树的复制、表达式前缀式

**中序遍历（Inorder Traversal）**
- 顺序：左子树 → 根节点 → 右子树
- 应用场景：二叉搜索树的中序遍历得到有序序列

**后序遍历（Postorder Traversal）**
- 顺序：左子树 → 右子树 → 根节点
- 应用场景：树的删除、表达式后缀式

#### 2.3.2 广度优先遍历（BFS）

**层序遍历（Level Order Traversal）**
- 顺序：从上到下，从左到右逐层访问
- 实现方式：使用队列辅助
- 应用场景：最短路径问题、拓扑排序

### 2.4 二叉树的存储结构

#### 2.4.1 顺序存储结构
**适用场景：** 完全二叉树

**存储方式：** 使用数组，按照层序编号存储
- 节点i的左孩子：2i
- 节点i的右孩子：2i+1
- 节点i的父节点：⌊i/2⌋

**优点：** 节省存储空间，访问速度快
**缺点：** 对非完全二叉树浪费空间

#### 2.4.2 链式存储结构
**适用场景：** 一般二叉树

**节点结构：**
```
struct TreeNode {
    T data;           // 数据域
    TreeNode *left;   // 左子节点指针
    TreeNode *right;  // 右子节点指针
}
```

**优点：** 灵活，空间利用率高
**缺点：** 指针占用额外空间

## 三、二叉搜索树（BST）

### 3.1 定义与性质

**二叉搜索树（Binary Search Tree）** 是一种特殊的二叉树，满足以下性质：
- 若左子树不空，则左子树上所有节点的值均小于根节点的值
- 若右子树不空，则右子树上所有节点的值均大于根节点的值
- 左右子树也分别为二叉搜索树

**核心性质：**
- 中序遍历得到升序序列
- 查找效率取决于树的形态

### 3.2 基本操作思路

#### 3.2.1 查找操作
**思路：**
- 从根节点开始比较
- 若目标值小于当前节点，递归查找左子树
- 若目标值大于当前节点，递归查找右子树
- 若相等，查找成功

**时间复杂度：**
- 最优情况：O(log n) - 树平衡时
- 最坏情况：O(n) - 树退化为链表时

#### 3.2.2 插入操作
**思路：**
- 首先执行查找操作，找到插入位置
- 若值已存在，则更新或忽略
- 若不存在，在查找失败的位置创建新节点

**关键点：** 插入位置总是叶子节点

#### 3.2.3 删除操作
**思路：** 分三种情况处理
1. **叶子节点**：直接删除
2. **单子树节点**：用子节点替代被删除节点
3. **双子树节点**：找到前驱或后继节点替代，然后删除前驱/后继节点

**前驱节点：** 左子树的最大值节点
**后继节点：** 右子树的最小值节点

## 四、树的变形与应用

### 4.1 平衡二叉搜索树

**问题：** 普通BST可能退化为链表，导致操作效率低下

**解决方案：** 通过旋转操作保持树的平衡

**常见类型：**
- **AVL树**：严格平衡，左右子树高度差≤1
- **红黑树**：近似平衡，通过颜色标记保持平衡

### 4.2 堆（Heap）

**定义：** 完全二叉树，满足堆性质

**类型：**
- **最大堆**：父节点的值≥子节点的值
- **最小堆**：父节点的值≤子节点的值

**应用：**
- 优先队列
- 堆排序
- Top-K问题

### 4.3 多路搜索树

**B树/B+树**
- 用于磁盘存储，减少I/O次数
- 每个节点可以有多个子节点
- 数据库索引的常用结构

## 六、树与其他数据结构的关系

### 6.1 树 vs 图
- 树是特殊的图（无环连通图）
- 图是树的泛化

### 6.2 树 vs 数组
- 树是非线性结构，数组是线性结构
- 树更适合表示层次关系

### 6.3 树 vs 链表
- 链表是退化为一维的树
- 树可以看作多维的链表

## 七、总结

**树的核心价值：**
1. **层次性**：天然适合表示层次关系
2. **效率性**：平衡树的操作效率高（O(log n)）
3. **灵活性**：可以适应多种应用场景

**学习重点：**
- 理解递归思想：树的定义和操作都基于递归
- 掌握遍历方法：前序、中序、后序、层序
- 理解平衡机制：AVL树、红黑树的平衡原理
- 熟悉应用场景：根据场景选择合适的树结构

**进阶方向：**
- 深入理解各种平衡树的实现机制
- 学习树的高级应用（线段树、字典树等）
- 掌握树的算法思想（递归、分治、回溯）
