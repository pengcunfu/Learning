# 堆（Heap）

## 一、堆的基本概念

### 1.1 堆的定义

**堆**是一种特殊的完全二叉树，分为**最大堆**和**最小堆**两种。

**最大堆（Max Heap）性质：**
```
对于堆中任意节点：
节点的值 ≥ 其子节点的值

即：父节点的值总是大于或等于子节点的值
```

**最小堆（Min Heap）性质：**
```
对于堆中任意节点：
节点的值 ≤ 其子节点的值

即：父节点的值总是小于或等于子节点的值
```

### 1.2 堆的直观理解

**最大堆示例：**
```
        [100]
       /    \
    [80]   [90]
   /  \   /  \
 [50][60][70][85]

堆顶（根节点）是最大值
```

**最小堆示例：**
```
        [10]
       /    \
    [20]   [30]
   /  \   /  \
 [50][60][70][80]

堆顶（根节点）是最小值
```

### 1.3 堆的重要性质

**性质1：结构性质**
- 堆是一棵**完全二叉树**
- 除了最后一层，其他层都必须填满
- 最后一层的节点尽可能靠左排列

**性质2：堆序性质**
- 最大堆：每个节点 ≥ 子节点
- 最小堆：每个节点 ≤ 子节点

**性质3：堆顶极值**
- 最大堆的堆顶是**最大值**
- 最小堆的堆顶是**最小值**

**性质4：部分有序**
- 只保证父子节点的大小关系
- 不保证兄弟节点的大小关系
- 不保证全局有序

## 二、堆的存储结构

### 2.1 数组表示

**为什么用数组？**
- 堆是完全二叉树
- 可以用数组高效存储
- 不需要指针，节省空间

**索引关系（0-based）：**
```
对于索引为i的节点：
- 父节点索引：(i-1) / 2
- 左子节点索引：2i + 1
- 右子节点索引：2i + 2
```

**示例：**
```
数组：[100, 80, 90, 50, 60, 70, 85]
索引： 0   1   2   3   4   5   6

对应的堆：
        [100] (索引0)
       /    \
    [80]   [90]     (索引1, 2)
   /  \   /  \
 [50][60][70][85]  (索引3, 4, 5, 6)
```

### 2.2 数组表示的优势

**优点：**
1. **空间效率高**
   - 不需要指针
   - 节省内存

2. **访问速度快**
   - 随机访问O(1)
   - 缓存友好

3. **实现简单**
   - 不需要复杂的指针操作
   - 通过索引计算即可

## 三、堆的核心操作

### 3.1 堆化（Heapify）

**堆化的定义：**
> 调整某个节点的位置，使其满足堆的性质

**下沉（Sift Down）操作：**
```
目的：将节点下沉到合适位置
适用：节点小于（最大堆）子节点

过程：
1. 比较节点与其子节点
2. 如果不满足堆性质，与较大的子节点交换
3. 继续向下，直到满足堆性质或到达底部
```

**上浮（Sift Up）操作：**
```
目的：将节点上浮到合适位置
适用：节点大于（最大堆）父节点

过程：
1. 比较节点与其父节点
2. 如果不满足堆性质，与父节点交换
3. 继续向上，直到满足堆性质或到达顶部
```

### 3.2 构建堆

**方法1：逐个插入**
```
时间复杂度：O(n log n)

过程：
1. 从空堆开始
2. 逐个插入元素
3. 每次插入后执行上浮操作
```

**方法2：批量构建（更优）**
```
时间复杂度：O(n)

过程：
1. 将元素按层序放入数组
2. 从最后一个非叶子节点开始
3. 对每个节点执行下沉操作
4. 直到根节点

为什么是O(n)？
- 大部分节点在底层，需要下沉的距离短
- 只有少数节点需要下沉较长的距离
- 数学证明：总操作次数 < 2n
```

### 3.3 插入操作

**插入思路：**
```
1. 将新元素放到堆的末尾（数组末尾）
2. 执行上浮操作
3. 恢复堆的性质
```

**时间复杂度：** O(log n)

**示例：**
```
最大堆插入95：
        [100]
       /    \
    [80]   [90]
   /  \   /  \
 [50][60][70][85]

步骤：
1. 添加95到末尾：
        [100]
       /    \
    [80]   [90]
   /  \   /  \
 [50][60][70][85]
                \
                [95]

2. 上浮95：
        [100]
       /    \
    [80]   [95]
   /  \   /  \
 [50][60][70][90]
```

### 3.4 删除操作

**删除堆顶（极值）：**
```
思路：
1. 保存堆顶元素
2. 将最后一个元素移到堆顶
3. 执行下沉操作
4. 恢复堆的性质
```

**时间复杂度：** O(log n)

**示例：**
```
最大堆删除堆顶100：
        [100]
       /    \
    [80]   [90]
   /  \   /  \
 [50][60][70][85]

步骤：
1. 移除100，将85移到堆顶：
        [85]
       /    \
    [80]   [90]
   /  \   /  \
 [50][60][70] __

2. 下沉85：
        [90]
       /    \
    [80]   [85]
   /  \   /  \
 [50][60][70] __
```

### 3.5 查找极值

**操作：**
- 最大堆：直接访问堆顶（数组第一个元素）
- 最小堆：直接访问堆顶（数组第一个元素）

**时间复杂度：** O(1)

## 四、堆的应用

### 4.1 优先队列

**什么是优先队列？**
> 普通队列：FIFO（先进先出）
> 优先队列：按优先级出队

**堆实现的优先队列：**
```
操作：
- insert(key)：插入元素，O(log n)
- extract_max/max()：取出优先级最高的元素，O(log n)
- peek()：查看最高优先级元素，O(1)
```

**应用场景：**
- 操作系统进程调度
- 网络数据包调度
- 事件驱动系统

### 4.2 堆排序

**堆排序思路：**
```
1. 构建最大堆
2. 重复以下操作：
   a. 交换堆顶和最后一个元素
   b. 堆大小减1
   c. 对新的堆顶执行下沉操作
```

**时间复杂度：**
- 构建堆：O(n)
- n次删除：O(n log n)
- 总时间：O(n log n)

**空间复杂度：** O(1) - 原地排序

**特点：**
- 不稳定排序
- 原地排序，空间效率高

### 4.3 Top-K问题

**问题定义：**
> 从海量数据中找出最大的K个元素

**堆的解决方案：**
```
使用最小堆：
1. 维护一个大小为K的最小堆
2. 遍历数据：
   - 如果堆未满，插入
   - 如果堆满且当前元素 > 堆顶，替换堆顶
3. 最后堆中的元素就是Top-K

时间复杂度：O(n log K)
空间复杂度：O(K)
```

**应用：**
- 搜索引擎Top-K结果
- 排行榜系统
- 数据分析

### 4.4 其他应用

**合并K个有序链表：**
```
使用最小堆：
1. 将K个链表的头节点放入最小堆
2. 重复：
   a. 取出堆顶（最小值）
   b. 将该链表的下一个节点放入堆
   c. 直到所有链表都遍历完

时间复杂度：O(n log K)
```

**求中位数：**
```
维护两个堆：
- 最大堆：存储较小的一半
- 最小堆：存储较大的一半
- 保持两个堆大小相等或差1

时间复杂度：O(log n)
```

**滑动窗口最大值：**
```
使用最大堆：
1. 维护窗口内的元素堆
2. 滑动时更新堆
3. 堆顶就是窗口最大值

时间复杂度：O(n log K)
```

## 五、堆的变种

### 5.1 二项堆（Binomial Heap）

**特点：**
- 由多棵二项树组成
- 支持高效的合并操作
- Fibonacci堆的基础

**操作复杂度：**
- 插入：O(log n)*，均摊O(1)
- 删除最小：O(log n)
- 合并：O(log n)*

### 5.2 斐波那契堆（Fibonacci Heap）

**特点：**
- 懒惰策略
- 理论性能优异
- 实现复杂

**操作复杂度：**
- 插入：O(1) 均摊
- 删除最小：O(log n) 均摊
- 减小关键字：O(1) 均摊

**应用：**
- Dijkstra算法的优化
- Prim算法的优化

### 5.3 配对堆（Pairing Heap）

**特点：**
- 实现简单
- 实际性能好
- 理论分析困难

## 六、堆的实现选择

### 6.1 数组 vs 指针

**数组实现（标准堆）：**
- 优点：
  - 简单高效
  - 缓存友好
  - 空间紧凑
- 缺点：
  - 大小固定或需要昂贵的resize

**指针实现（树堆）：**
- 优点：
  - 动态大小
  - 灵活性高
- 缺点：
  - 指针开销
  - 缓存不友好
  - 实现复杂

### 6.2 最大堆 vs 最小堆

**选择标准：**
- 需要最大值 → 最大堆
- 需要最小值 → 最小堆
- 只需要转换符号即可

## 七、堆的优缺点分析

### 7.1 优点

1. **极值访问快**
   - O(1)时间访问最大/最小值

2. **插入删除效率高**
   - O(log n)时间
   - 性能稳定

3. **实现简单**
   - 数组实现简洁
   - 易于理解和实现

4. **空间效率高**
   - 不需要额外指针
   - 紧凑存储

5. **原地排序**
   - 堆排序空间O(1)
   - 适合大数据排序

### 7.2 缺点

1. **不支持随机访问**
   - 无法直接访问第k个元素
   - 无法查找特定元素

2. **不支持高效的范围查询**
   - 只保证部分有序
   - 不能按序遍历

3. **不适合查找操作**
   - 查找特定元素需要O(n)
   - 不是查找的最佳结构

### 7.3 与其他结构的比较

| 操作 | 堆 | 平衡树 | 有序数组 |
|------|----|-------|---------|
| 查找极值 | O(1) | O(log n) | O(1) |
| 插入 | O(log n) | O(log n) | O(n) |
| 删除极值 | O(log n) | O(log n) | O(n) |
| 查找元素 | O(n) | O(log n) | O(log n) |
| 有序遍历 | 不支持 | 支持 | 支持 |

## 八、实践考虑

### 8.1 堆的容量管理

**动态扩容：**
```
策略：
1. 初始容量设为合理值
2. 当堆满时，扩容为2倍
3. 当利用率低于1/4时，缩容为1/2

均摊时间复杂度：O(1)
```

### 8.2 堆的并发访问

**线程安全：**
- 使用锁保护共享堆
- 或使用无锁堆（复杂）

### 8.3 堆的优化

**批量操作：**
- 批量插入后统一堆化
- 比逐个插入更高效

**缓存优化：**
- 合理安排数据布局
- 提高缓存命中率
