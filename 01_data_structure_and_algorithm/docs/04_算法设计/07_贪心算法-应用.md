# 贪心算法应用（Greedy Algorithm Applications）

## 一、贪心算法思想回顾

### 1.1 贪心策略

**核心思想：**
> 在对问题求解时，总是做出在当前看来是最好的选择

**特点：**
1. **局部最优**：每一步选择当前最好的
2. **不可撤销**：一旦选择，不再改变
3. **不保证全局最优**：可能得到次优解

### 1.2 贪心算法的适用性

**适用情况：**
1. **具有贪心选择性质**
2. **最优子结构**
3. **无后效性**

**不适用情况：**
1. 需要考虑全局情况
2. 存在循环依赖
3. 需要回溯尝试

## 二、经典贪心算法问题

### 2.1 活动选择问题（Activity Selection）

**问题描述：**
> 有n个活动，每个活动有开始时间s[i]和结束时间f[i]，求能参加的最大活动数量

**贪心策略：**
```
按结束时间排序
每次选择结束最早且与已选活动不冲突的活动
```

**为什么这样贪心？**
```
直觉：选结束早的，给后面留更多空间
证明：可以证明这种策略最优
```

**算法：**
```
1. 按结束时间排序活动
2. selected = {}
3. for each 活动 in 排序后的列表:
    if 活动.开始 >= 上一个活动.结束:
        selected.add(活动)
4. return selected
```

### 2.2 区间调度问题

**变体1：区间覆盖**
```
给定一组区间，选择最少数量的区间覆盖目标区间
```

**贪心策略：**
```
1. 按起点排序
2. 选择覆盖最多的区间
3. 移除已覆盖部分
4. 重复
```

**变体2：区间合并**
```
合并重叠的区间
```

### 2.3 背包问题（Knapsack Problem）

**0-1背包问题：**
```
给定n个物品，物品i的价值为v[i]，重量为w[i]
背包容量为W，求价值最大
```

**贪心策略（不一定最优）：**
```
策略1：按价值贪心
策略2：按重量贪心
策略3：按价值密度贪心（v[i]/w[i]）

注意：贪心不一定得到最优解！
需要用动态规划求解
```

**分数背包问题：**
```
可以取物品的一部分
贪心（按价值密度）可以得到最优解
```

### 2.4 哈夫曼编码（Huffman Coding）

**问题：**
> 给定字符及其频率，构造最短的前缀编码

**贪心策略：**
```
1. 每次选择频率最小的两个节点合并
2. 新节点的频率是两个节点频率之和
3. 重复直到只剩一个节点
```

**为什么正确？**
```
可以证明这样得到前缀码的最短总长度
```

## 三、其他贪心算法问题

### 3.1 最小生成树

**Prim算法：**
```
贪心：每次选择连接树的最小边
```

**Kruskal算法：**
```
贪心：每次选择全局最小的边
```

### 3.2 单源最短路径

**Dijkstra算法：**
```
贪心：每次选择距离最小的未访问顶点
```

### 3.3 分数背包问题

**贪心策略：**
```
按价值密度（vi/wi）降序贪心
每次选择价值密度最高的物品
```

## 四、贪心算法的证明方法

### 4.1 交换论证

**思路：**
```
1. 假设贪心解为G
2. 设最优解为O
3. 将O调整为G的步骤
4. 证明调整后不比O差
5. 因此G也是最优的
```

### 4.2 归约法

**思路：**
```
将问题P归约为另一个已知的问题Q
如果能用贪心解决q，则p也能用贪心
```

## 五、贪心算法的优化技巧

### 5.1 排序

**关键：**
```
贪心算法通常依赖于特定顺序
排序是第一步
```

**示例：**
```
活动选择：按结束时间排序
分数背包：按价值密度排序
```

### 5.2 数据结构

**优先队列：**
```
高效获取最小/最大元素
O(log n)插入和删除
```

**并查集：**
```
高效维护集合关系
支持快速合并和查询
```

### 5.3 剪枝

**提前终止：**
```
如果已经找到足够好的解
可以提前停止搜索
```

## 六、贪心 vs 动态规划

| 问题 | 贪心 | DP |
|------|------|----|
| 0-1背包 | 不一定最优 | 最优 |
| 分数背包 | 最优 | 最优 |
| 活动选择 | 最优 | 过于复杂 |
| 最小生成树 | 最优 | 过于复杂 |

## 七、总结

**贪心算法简单高效，但需要证明其正确性。**
