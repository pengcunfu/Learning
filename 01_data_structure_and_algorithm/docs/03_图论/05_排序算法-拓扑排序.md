# 拓扑排序（Topological Sort）

## 一、基本概念

### 1.1 什么是拓扑排序？

**拓扑排序**是对**有向无环图（DAG）**的顶点进行排序，使得对于图中的每一条有向边 (u, v)，顶点u在排序中都出现在顶点v之前。

**关键点：**
- 只适用于**有向图**
- 图必须**无环**（DAG）
- 结果可能**不唯一**

**直观理解：**
```
任务A必须完成后才能做任务B
那么在拓扑排序中，A必须排在B前面
```

### 1.2 拓扑排序的应用

**典型应用场景：**

1. **任务调度**
   - 项目管理中的任务依赖
   - 课程先修关系
   - 构建系统的依赖关系

2. **编译系统**
   - 源文件编译顺序
   - 模块依赖关系

3. **死锁检测**
   - 操作系统资源分配
   - 数据库事务调度

### 1.3 有向无环图（DAG）

**定义：**
> 如果一个有向图中不存在环，则称为有向无环图

**为什么不能有环？**
```
有环的情况：
A → B → C → A

无法确定先后顺序！
A需要B完成，B需要C完成，C又需要A完成
形成循环依赖，无法调度
```

## 二、拓扑排序的算法

### 2.1 Kahn算法（基于入度）

**核心思想：**
> 不断选择入度为0的顶点，放入排序结果

**算法步骤：**
```
1. 计算所有顶点的入度
2. 将所有入度为0的顶点放入队列
3. 当队列不为空：
   a. 取出一个顶点u，加入排序结果
   b. 删除u的所有出边
   c. 将受影响的顶点入度减1
   d. 若有顶点入度变为0，加入队列
4. 重复直到队列为空
```

**示例：**
```
课程依赖关系：
A → B → D
  ↘ C ↗

步骤1：计算入度
A:0, B:2, C:1, D:2

步骤2：A入队，排序=[]
队列：[A]

步骤3：处理A
排序=[A]
删除A的边后：B:1, C:0
C入队：[C]

步骤4：处理C
排序=[A, C]
删除C的边后：B:0, D:1
B入队：[B]

步骤5：处理B
排序=[A, C, B]
删除B的边后：D:0
D入队：[D]

步骤6：处理D
排序=[A, C, B, D]

最终结果：A, C, B, D
```

### 2.2 DFS算法（深度优先搜索）

**核心思想：**
> 利用DFS的完成时间进行排序

**算法步骤：**
```
1. 对每个未访问的顶点进行DFS
2. 在DFS回溯时（访问完所有邻接点后），
   将当前顶点加入结果列表的前面
3. 最终得到的列表就是拓扑排序
```

**为什么这样有效？**
```
DFS的特性：后序遍历
当访问完u的所有邻接点后，
说明u的所有后继都已经处理完成
此时将u加入结果，u一定在其后继前面
```

**示例：**
```
图结构：
A → B → D
  ↘ C ↗

DFS过程：
访问A → 访问B → 访问D → D完成 → B完成
      ↘ 访问C → C完成 → A完成

加入结果顺序（逆序）：
D, B, C, A

最终排序：A, C, B, D
```

### 2.3 两种算法的比较

| 特性 | Kahn算法 | DFS算法 |
|------|---------|---------|
| **数据结构** | 队列 | 递归/栈 |
| **实现复杂度** | 较简单 | 较复杂 |
| **空间复杂度** | O(V) | O(V) |
| **时间复杂度** | O(V+E) | O(V+E) |
| **是否贪心** | 是 | 否 |
| **检测环** | 容易 | 需要额外处理 |

## 三、环的检测

### 3.1 为什么需要检测环？

**有环的影响：**
- 无法完成拓扑排序
- 存在循环依赖
- 系统可能出现死锁

### 3.2 Kahn算法的环检测

**检测方法：**
```
如果最终排序结果的顶点数 < 图的总顶点数，
则图中存在环
```

**原理：**
```
有环的图：
A → B → C
      ↑   ↓
      └───┘

所有顶点入度都≥1
队列始终为空
无法继续处理
```

### 3.3 DFS算法的环检测

**检测方法：**
```
在DFS中维护访问状态：
- 未访问（WHITE）
- 访问中（GRAY）
- 已完成（BLACK）

如果遇到访问中的节点，说明存在环
```

**状态转换：**
```
未访问 → 访问中 → 已完成
   ↑         |
   └─────────┘ 发现回边（环）
```

## 四、拓扑排序的实现要点

### 4.1 数据结构选择

**Kahn算法需要的结构：**
```
1. 邻接表：存储图
2. 入度数组：记录每个顶点的入度
3. 队列：存储入度为0的顶点
4. 结果列表：存储排序结果
```

**DFS算法需要的结构：**
```
1. 邻接表：存储图
2. 访问数组：标记访问状态
3. 状态数组：标记节点状态（WHITE/GRAY/BLACK）
4. 结果列表：存储排序结果
```

### 4.2 实现注意事项

**邻接表的构建：**
- 需要维护入度信息
- 或者单独计算入度

**队列的选择：**
- 普通队列：FIFO
- 优先队列：可以得到特定顺序的拓扑排序

**结果存储：**
- 可以用数组或列表
- DFS算法需要支持头插或逆序

## 五、拓扑排序的应用实例

### 5.1 课程安排

**问题：**
```
课程先修关系：
课程A → 课程B
课程A → 课程C
课程B → 课程D
课程C → 课程D

如何安排学习顺序？
```

**拓扑排序结果：**
```
A → B → D
  ↘ C ↗

学习顺序：A, B, C, D 或 A, C, B, D
```

### 5.2 任务调度

**项目任务依赖：**
```
设计 → 编码 → 测试
  ↘ 文档 ↗

拓扑排序：设计, 编码, 文档, 测试
（文档可以在编码期间并行进行）
```

### 5.3 编译依赖

**模块依赖：**
```
main.o: main.c util.h
util.o: util.c util.h
链接：main.o util.o → executable

编译顺序：
1. 先编译util.c → util.o
2. 再编译main.c → main.o
3. 最后链接 → executable
```

## 六、拓扑排序的扩展

### 6.1 带权拓扑排序

**应用场景：**
- 任务有时间估计
- 需要优化完成时间

**算法改进：**
- 使用优先队列
- 按优先级选择顶点
- 得到"最优"的拓扑排序

### 6.2 最长路径

**在DAG中求最长路径：**
1. 先进行拓扑排序
2. 按拓扑序动态规划
3. dp[u] = max(dp[v] + weight(u,v))

**应用：**
- 项目关键路径分析
- 最长工期计算

### 6.3 字典序最小拓扑排序

**目标：**
- 在所有可能的拓扑排序中
- 找到字典序最小的那个

**方法：**
- 使用优先队列（最小堆）
- 每次选择编号最小的顶点

## 七、拓扑排序与其他算法的关系

### 7.1 与DFS的关系

**联系：**
- 都是基于图的遍历
- 都使用递归或栈
- 都能检测环

**区别：**
- DFS是通用遍历
- 拓扑排序是特殊处理

### 7.2 与关键路径法的关系

**CPM（关键路径法）：**
- AOV网（Activity On Vertex）→ 拓扑排序
- AOE网（Activity On Edge）→ 关键路径

### 7.3 与强连通分量的关系

**Kosaraju算法：**
1. 对图进行DFS
2. 反转图
3. 再次DFS
4. 得到强连通分量

**Tarjan算法：**
- 一次DFS完成
- 更高效

## 八、性能分析

### 8.1 时间复杂度

**两种算法：**
- Kahn算法：O(V + E)
- DFS算法：O(V + E)

**分析：**
- V个顶点都要处理
- E条边都要检查
- 邻接表表示是线性时间

### 8.2 空间复杂度

**两种算法：**
- Kahn算法：O(V) - 需要队列和入度数组
- DFS算法：O(V) - 递归栈或显式栈

### 8.3 实际性能

**影响因素：**
- 图的稀疏程度
- 邻接表的实现
- 缓存性能

**优化建议：**
- 使用高效的队列
- 减少不必要的拷贝
- 考虑并行化

## 九、总结

### 9.1 核心要点

1. **拓扑排序的本质**
   - DAG的线性化
   - 保持依赖关系的顺序

2. **两种算法的思想**
   - Kahn：贪心选择入度为0的顶点
   - DFS：利用完成时间排序

3. **环的检测**
   - 有环图无法拓扑排序
   - 需要特殊的检测机制

4. **广泛应用**
   - 任务调度
   - 编译系统
   - 课程安排
