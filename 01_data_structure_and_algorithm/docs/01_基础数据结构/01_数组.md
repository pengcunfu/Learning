# 数组（Array）

## 一、数组概述

### 1.1 什么是数组？

**数组：**
> 相同类型元素的有序集合，在内存中连续存储

**核心特点：**
```
1. 相同类型：所有元素必须是相同的数据类型
2. 有序排列：元素按照索引顺序存储
3. 连续内存：在内存中占用连续的存储空间
4. 索引访问：通过下标快速访问元素
```

### 1.2 数组的内存模型

**内存布局：**
```
地址：  1000    1004    1008    1012    1016
       ┌────┐  ┌────┐  ┌────┐  ┌────┐  ┌────┐
索引：  │ 0  │  │ 1  │  │ 2  │  │ 3  │  │ 4  │
       └────┘  └────┘  └────┘  └────┘  └────┘
       ┌────┐  ┌────┐  ┌────┐  ┌────┐  ┌────┐
数据：  │ 10 │  │ 20 │  │ 30 │  │ 40 │  │ 50 │
       └────┘  └────┘  └────┘  └────┘  └────┘

数组起始地址 = 1000
每个元素大小 = 4字节
```

**地址计算：**
```
元素i的地址 = 起始地址 + i × 元素大小

例：arr[3]的地址 = 1000 + 3 × 4 = 1012
```

## 二、数组的分类

### 2.1 按维度分类

**一维数组：**
```
结构：线性排列
用途：简单数据序列
示例：[1, 2, 3, 4, 5]
```

**二维数组：**
```
结构：矩阵形式
用途：表格数据、图像
示例：[[1,2,3], [4,5,6]]

内存存储：按行优先或列优先
行优先：[1,2,3,4,5,6] (C/C++)
列优先：[1,4,2,5,3,6] (Fortran)
```

**多维数组：**
```
结构：多维空间
用途：科学计算、张量
示例：三维数组（立方体数据）
```

### 2.2 按存储方式分类

**静态数组：**
```
特点：
- 编译时确定大小
- 栈上分配或全局数据区
- 大小固定，不可改变

优点：访问快速，管理简单
缺点：灵活性差，可能浪费空间
```

**动态数组：**
```
特点：
- 运行时分配内存
- 堆上分配
- 可动态调整大小

优点：灵活高效
缺点：需要手动管理内存
```

## 三、数组的操作

### 3.1 基本操作

**访问元素：**
```
操作：arr[index]
时间：O(1)
原理：通过索引直接计算地址
```

**修改元素：**
```
操作：arr[index] = value
时间：O(1)
原理：直接修改内存位置
```

**获取长度：**
```
操作：length/size属性
时间：O(1)
原理：记录数组大小
```

### 3.2 插入操作

**在末尾插入：**
```
时间：O(1)（假设有空间）

步骤：
1. 检查数组是否已满
2. 将元素放在arr[length]位置
3. 更新长度
```

**在指定位置插入：**
```
时间：O(n)

步骤：
1. 检查位置是否有效
2. 从后向前移动元素
3. 在指定位置插入元素
4. 更新长度

原因：需要移动n-i个元素
```

### 3.3 删除操作

**删除末尾元素：**
```
时间：O(1)

步骤：
1. 减少数组长度
2. 元素自动被忽略
```

**删除指定位置元素：**
```
时间：O(n)

步骤：
1. 从删除位置开始
2. 后续元素向前移动
3. 更新长度

原因：需要移动n-i-1个元素
```

### 3.4 查找操作

**按索引查找：**
```
时间：O(1)
原理：直接计算地址
```

**按值查找：**
```
时间：O(n)
方法：线性搜索
优化：有序数组可用二分查找O(log n)
```

## 四、数组的优缺点

### 4.1 优点

**快速访问：**
```
O(1)随机访问
通过索引直接定位
```

**内存连续：**
```
缓存友好
局部性好
预取效率高
```

**简单高效：**
```
实现简单
管理方便
```

### 4.2 缺点

**大小固定：**
```
静态数组：编译时确定
动态数组：需要重新分配
```

**插入删除低效：**
```
需要移动元素
最坏O(n)时间
```

**空间浪费：**
```
可能分配过多空间
内存利用率不高
```

## 五、动态数组的实现原理

### 5.1 容量管理

**基本概念：**
```
容量（Capacity）：数组的总大小
大小（Size）：实际元素个数
```

**扩容策略：**
```
触发条件：Size == Capacity

策略1：倍增扩容
- 新容量 = 旧容量 × 2
- 均摊时间复杂度：O(1)
- 最坏情况：O(n)

策略2：固定增量
- 新容量 = 旧容量 + 固定值
- 可能导致频繁扩容
```

**缩容策略：**
```
触发条件：Size < Capacity / 4
新容量 = Capacity / 2

目的：避免空间浪费
```

### 5.2 时间复杂度分析

**均摊分析：**
```
假设：每次扩容2倍
初始容量：1
插入n个元素

扩容次数：log n
每次扩容成本：1, 2, 4, 8, ..., n
总成本：2n
均摊成本：O(1)
```

## 七、数组vs其他结构

### 7.1 vs 链表

| 特性 | 数组 | 链表 |
|------|------|------|
| **访问** | O(1) | O(n) |
| **插入删除** | O(n) | O(1)已知位置 |
| **内存** | 连续 | 分散 |
| **大小** | 固定 | 动态 |
| **缓存** | 友好 | 不友好 |

### 7.2 vs 动态数组

| 特性 | 静态数组 | 动态数组 |
|------|----------|----------|
| **大小** | 固定 | 可变 |
| **分配** | 栈/全局 | 堆 |
| **管理** | 自动 | 手动/自动 |
| **效率** | 更高 | 略低 |

## 八、数组的高级话题

### 8.1 数组与缓存

**缓存原理：**
```
空间局部性：
- 相邻元素在同一缓存行
- 预取提高命中率

时间局部性：
- 最近访问可能再次访问
```

**优化技巧：**
```
1. 按行访问二维数组
2. 数据对齐
3. 避免缓存冲突
```

### 8.2 数组的边界

**越界问题：**
```
原因：
- 索引为负数
- 索引超过长度

后果：
- 访问非法内存
- 程序崩溃
- 安全漏洞

防护：
- 边界检查
- 使用安全库函数
```

### 8.3 多维数组优化

**存储优化：**
```
1. 选择合适的遍历顺序
2. 数据局部性优化
3. 分块处理
```

## 九、总结

**数组是最基础的数据结构，通过连续内存和索引机制实现O(1)访问，是构建复杂数据结构的基础。**

**核心要点：**
1. 内存连续，索引直接访问
2. 适合读多写少场景
3. 缓存友好，性能优越
4. 插入删除需要移动元素

**选择数组的情况：**
- 需要快速随机访问
- 数据量相对稳定
- 重视缓存性能

**不选择数组的情况：**
- 频繁插入删除
- 数据量变化大
- 内存空间紧张
