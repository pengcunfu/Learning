# 映射（Map）

## 一、映射概述

### 1.1 什么是映射？

**映射：**
> 存储键值对（Key-Value Pair）的数据结构，通过键快速查找对应的值

**核心概念：**
```
键（Key）：唯一标识，用于查找
值（Value）：实际存储的数据
映射关系：Key → Value
```

**类比：**
```
字典：
- 键：单词
- 值：释义

通讯录：
- 键：姓名
- 值：电话号码
```

### 1.2 映射的特点

**基本特性：**
```
1. 键唯一性：每个键只能出现一次
2. 键值关联：每个键关联一个值
3. 快速查找：通过键快速定位值
4. 动态大小：可以动态增删
```

## 二、映射的实现

### 2.1 基于哈希表

**HashMap：**
```
最常见的映射实现

原理：
- 哈希函数：hash(key)
- 数组存储：按哈希值存储
- 冲突处理：链地址法或开放寻址

时间复杂度：
- 平均：O(1)
- 最坏：O(n)
```

**优点：**
```
快速查找
灵活的键类型
动态大小
```

**缺点：**
```
无序
最坏情况性能
需要好的哈希函数
```

### 2.2 基于树的映射

**TreeMap：**
```
基于红黑树实现

特点：
- 有序：按键的顺序
- 保证：O(log n)
- 范围查询
```

**优点：**
```
有序性
性能保证
丰富操作
```

**缺点：**
```
常数较大
实现复杂
键需要可比较
```

### 2.3 其他实现

**LinkedHashMap：**
```
哈希表 + 双向链表
保持插入顺序或访问顺序
```

**WeakHashMap：**
```
弱引用键
自动清理无用条目
```

**ConcurrentHashMap：**
```
线程安全
分段锁
高并发性能
```

## 三、映射的基本操作

### 3.1 核心操作

**插入/更新：**
```
put(key, value):
- 计算key的哈希值或位置
- 如果key存在，更新value
- 如果key不存在，插入新键值对

时间：取决于实现
```

**查找：**
```
get(key):
- 计算key的哈希值或位置
- 查找对应的value
- 不存在返回null或特殊值

时间：取决于实现
```

**删除：**
```
remove(key):
- 查找key
- 删除键值对

时间：取决于实现
```

**包含判断：**
```
containsKey(key):
- 判断key是否存在

时间：取决于实现
```

### 3.2 视图操作

**键集合：**
```
keySet():
返回所有键的集合

特点：
- 键唯一
- 可以遍历
- 可以删除
```

**值集合：**
```
values():
返回所有值的集合

特点：
- 值可能重复
- 可以遍历
```

**键值对集合：**
```
entrySet():
返回所有键值对的集合

特点：
- 可以同时访问键和值
- 可以修改值
```

## 四、映射的高级操作

### 4.1 批量操作

**批量插入：**
```
putAll(map):
将另一个映射的所有键值对插入

时间：O(n)
```

**批量查找：**
```
get(keys):
查找多个键的值

可能优化：
- 减少哈希计算
- 批量处理
```

### 4.2 查询操作

**最大最小键：**
```
maxKey(), minKey():
需要有序映射

时间：O(log n)
```

**范围查询：**
```
subMap(from, to):
获取键在范围内的所有键值对

需要有序映射
```

**前驱后继：**
```
lowerKey(key): 小于key的最大键
higherKey(key): 大于key的最小键

需要有序映射
```

## 五、映射的应用

### 5.1 缓存系统

**LRU缓存：**
```
问题：实现最近最少使用缓存

解决：
- LinkedHashMap
- 访问顺序模式
- 达到容量时删除最旧项

应用：
- 浏览器缓存
- 数据库查询缓存
```

### 5.2 计数器

**词频统计：**
```
问题：统计词频

解决：
Map<String, Integer>
- 单词作为键
- 频次作为值

应用：
- 文本分析
- 推荐系统
```

### 5.3 配置管理

**系统配置：**
```
问题：存储配置参数

解决：
Map<String, String>
- 参数名作为键
- 参数值作为值

优点：
- 快速查找
- 动态配置
```

### 5.4 索引结构

**倒排索引：**
```
问题：从内容找文档

解决：
Map<String, List<Document>>
- 单词作为键
- 文档列表作为值

应用：
- 搜索引擎
- 全文检索
```

## 六、映射vs其他结构

### 6.1 vs 集合

| 特性 | 映射 | 集合 |
|------|------|------|
| **元素** | 键值对 | 单值 |
| **查找** | 通过键 | 通过值 |
| **目的** | 关联 | 去重 |
| **重复** | 键唯一 | 值唯一 |

**关系：**
```
集合可以用只有键的映射实现
```

### 6.2 vs 数组

| 特性 | 映射 | 数组 |
|------|------|------|
| **索引** | 任意键 | 整数索引 |
| **查找** | O(1)平均 | O(n) |
| **大小** | 动态 | 固定 |
| **内存** | 较大 | 较小 |

### 6.3 vs 对象

**相似性：**
```
都是键值对存储
都可以属性访问
```

**区别：**
```
映射：
- 键可以是任意类型
- 动态增删
- 大小可变

对象：
- 键通常是字符串
- 结构固定
- 编译时确定
```

## 七、映射的性能

### 7.1 时间复杂度

**HashMap：**
```
插入：O(1)平均
查找：O(1)平均
删除：O(1)平均

最坏：O(n)
```

**TreeMap：**
```
插入：O(log n)
查找：O(log n)
删除：O(log n)

保证：O(log n)
```

### 7.2 空间复杂度

```
O(n)

额外空间：
HashMap：负载因子、指针
TreeMap：树节点、多个指针
```

### 7.3 性能优化

**容量规划：**
```
初始容量：
- 避免频繁扩容
- 根据预期大小设置

负载因子：
- 平衡时间和空间
- 默认0.75
```

**哈希函数：**
```
好的哈希函数：
- 分布均匀
- 计算快速
- 减少冲突
```

## 八、映射的选择

### 8.1 HashMap

```
需要快速查找
不关心顺序
键可哈希
```

**特点：**
```
最快平均性能
无序
最广泛使用
```

### 8.2 TreeMap

**使用场景：**
```
需要有序
需要范围查询
需要最值
```

**特点：**
```
保证性能
有序
功能丰富
```

### 8.3 LinkedHashMap

**使用场景：**
```
需要保持顺序
快速查找
实现LRU
```

**特点：**
```
两种顺序：
- 插入顺序
- 访问顺序
```

## 九、映射的实现细节

### 9.1 哈希冲突处理

**链地址法：**
```
每个位置维护链表
冲突元素添加到链表

优点：
- 简单
- 删除方便

缺点：
- 链表可能过长
- 缓存不友好
```

**开放寻址法：**
```
所有数据在数组内
冲突时寻找下一个空位

优点：
- 缓存友好
- 空间紧凑

缺点：
- 删除复杂
- 聚集现象
```

### 9.2 扩容机制

**触发条件：**
```
元素数量 > 容量 × 负载因子
```

**扩容策略：**
```
1. 分配更大数组（通常2倍）
2. 重新哈希所有元素
3. 释放旧数组

时间：O(n)
```

## 十、映射的高级话题

### 10.1 并发映射

**问题：**
```
多线程访问
数据一致性
性能要求
```

**解决：**
```
ConcurrentHashMap：
- 分段锁
- 高并发
- 读不加锁

ConcurrentSkipListMap：
- 跳表实现
- 有序
- 高并发
```

### 10.2 持久化映射

**定义：**
```
修改后保持旧版本
函数式编程常用
```

**实现：**
```
路径复制
结构共享
```

### 10.3 分布式映射

**问题：**
```
跨机器存储
数据分片
一致性
```

**解决：**
```
一致性哈希
分片策略
复制机制
```

## 十一、总结

**映射是键值对的存储结构，通过不同的数据结构实现，提供了高效的键值查找和丰富的关联操作。**

**核心要点：**
1. 键值对存储
2. 键唯一性
3. 快速查找
4. 多种实现

**实现选择：**
- 快速查找 → HashMap
- 需要有序 → TreeMap
- 保持顺序 → LinkedHashMap
- 高并发 → ConcurrentHashMap

**典型应用：**
- 缓存系统
- 计数器
- 配置管理
- 索引结构

**注意事项：**
- 键需要正确实现equals和hashCode（哈希映射）
- 键需要不可变（最佳实践）
- 值可以是任意对象
- 选择合适的初始容量
