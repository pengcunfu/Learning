# 哈希表（Hash Table）

## 一、哈希表概述

### 1.1 什么是哈希表？

**哈希表：**
> 一种通过哈希函数实现快速查找的数据结构，提供键值对（Key-Value）的存储

**核心思想：**
```
通过哈希函数将键映射到存储位置
实现O(1)时间的查找、插入、删除
```

**基本组成：**
```
1. 键（Key）：用于标识和查找
2. 值（Value）：实际存储的数据
3. 哈希函数：将键转换为索引
4. 存储数组：实际存储数据
```

### 1.2 为什么需要哈希表？

**查找问题的演进：**
```
数组/链表：O(n)线性查找
有序数组：O(log n)二分查找
哈希表：O(1)直接查找
```

**优势：**
```
1. 极快的查找速度
2. 灵活的键类型
3. 动态大小
4. 简单的接口
```

## 二、哈希函数

### 2.1 哈希函数的要求

**理想特性：**
```
1. 确定性：相同输入产生相同输出
2. 快速计算：O(1)时间复杂度
3. 均匀分布：减少冲突
4. 雪崩效应：输入微小变化导致输出巨大变化
```

**好的哈希函数：**
```
- 计算简单
- 分布均匀
- 冲突最少
```

### 2.2 常见哈希函数

**除法哈希：**
```
hash(key) = key % m

m选择：
- 最好是质数
- 避免与数据特性相关
```

**乘法哈希：**
```
hash(key) = floor(m × (key × A mod 1))

A ≈ 0.618（黄金比例）
```

**字符串哈希：**
```
多项式滚动哈希：
hash = Σ(s[i] × p^i) % m

p通常选择31或37（质数）
```

### 2.3 哈希函数的评估

**评估标准：**
```
1. 分布均匀性
2. 计算速度
3. 冲突率
4. 雪崩效应
```

## 三、冲突处理

### 3.1 冲突的产生

**什么是冲突？**
```
当两个不同的键映射到同一个位置时
hash(key1) == hash(key2)
```

**必然性：**
```
鸽巢原理：
键的可能数量 > 数组大小
冲突不可避免
```

### 3.2 开放寻址法

**基本思想：**
```
当位置被占用时，按某种规则寻找下一个空位
所有数据存储在数组内部
```

**线性探测：**
```
规则：h(k), h(k)+1, h(k)+2, ...

优点：简单，缓存友好
缺点：聚集现象
```

**二次探测：**
```
规则：h(k), h(k)+1², h(k)+2², ...

优点：减少聚集
缺点：可能无法探测所有位置
```

**双重哈希：**
```
规则：h(k), h(k)+h2(k), h(k)+2×h2(k), ...

优点：分布均匀
缺点：计算复杂
```

### 3.3 链地址法

**基本思想：**
```
每个位置维护一个链表
冲突的元素添加到链表中
```

**实现：**
```
数组每个位置是一个链表头
插入：O(1)平均
查找：O(n/m)平均，n为元素数，m为表大小
```

**优点：**
```
1. 简单直观
2. 处理冲突能力强
3. 删除操作简单
```

**缺点：**
```
1. 需要额外指针空间
2. 缓存不友好
3. 链表可能过长
```

### 3.4 其他方法

**再哈希：**
```
使用多个哈希函数
冲突时尝试下一个哈希函数
```

**公共溢出区：**
```
基本表存储主要数据
冲突元素放入溢出区
```

## 四、哈希表的操作

### 4.1 查找操作

**链地址法：**
```
1. 计算哈希值
2. 定位到对应链表
3. 在链表中查找

时间：O(1)平均，O(n)最坏
```

**开放寻址法：**
```
1. 计算哈希值
2. 按探测序列查找
3. 直到找到或遇到空位

时间：O(1)平均，O(n)最坏
```

### 4.2 插入操作

**链地址法：**
```
1. 计算哈希值
2. 在链表中检查是否已存在
3. 不存在则插入链表头部

时间：O(1)平均
```

**开放寻址法：**
```
1. 计算哈希值
2. 按探测序列找空位
3. 插入数据

时间：O(1)平均
```

### 4.3 删除操作

**链地址法：**
```
1. 计算哈希值
2. 在链表中查找并删除

时间：O(1)平均
```

**开放寻址法：**
```
问题：不能直接删除
解决：标记为"已删除"

时间：O(1)平均
```

## 五、性能分析

### 5.1 负载因子

**定义：**
```
α = 元素数量 / 表大小

意义：
- 反映哈希表的填充程度
- 影响性能的关键因素
```

**影响：**
```
α过小：空间浪费
α过大：冲突增多

理想范围：0.6 - 0.75
```

### 5.2 时间复杂度

**查找：**
```
平均：O(1)
最坏：O(n)

成功查找：≈ 1 + α/2
失败查找：≈ 1 + α
```

**插入：**
```
平均：O(1)
最坏：O(n)
```

**删除：**
```
平均：O(1)
最坏：O(n)
```

### 5.3 空间复杂度

```
O(n)

数组：O(m)
链表指针：O(n)
总空间：O(m + n)
```

## 六、哈希表的扩容

### 6.1 扩容时机

**触发条件：**
```
负载因子超过阈值
通常α > 0.75
```

### 6.2 扩容策略

**步骤：**
```
1. 分配更大的数组（通常2倍）
2. 重新哈希所有元素
3. 释放旧数组
```

**注意：**
```
扩容是昂贵操作：O(n)
但均摊后仍为O(1)
```

## 八、哈希表vs其他结构

### 8.1 vs 数组

| 特性 | 哈希表 | 数组 |
|------|--------|------|
| **查找** | O(1) | O(n)/O(log n) |
| **插入** | O(1) | O(n) |
| **有序** | 无 | 有 |
| **内存** | 较大 | 较小 |

### 8.2 vs 平衡树

| 特性 | 哈希表 | 平衡树 |
|------|--------|--------|
| **查找** | O(1) | O(log n) |
| **有序** | 无 | 有 |
| **实现** | 简单 | 复杂 |
| **最坏情况** | O(n) | O(log n) |

**选择建议：**
```
需要快速查找 → 哈希表
需要有序遍历 → 平衡树
```

## 九、哈希表的高级话题

### 9.1 完美哈希

**定义：**
```
无冲突的哈希函数
```

**应用：**
```
关键字集合固定
编译时确定
```

### 9.2 布隆过滤器

**思想：**
```
位数组 + 多个哈希函数
空间高效的概率数据结构
```

**应用：**
```
判断元素是否存在
允许假阳性
```

### 9.3 一致性哈希

**问题：**
```
分布式系统中节点变化
导致大量数据迁移
```

**解决：**
```
将节点和数据都哈希到环上
顺时针查找最近节点
最小化数据迁移
```

## 十、总结

**哈希表是通过哈希函数实现O(1)查找的高效数据结构，是现代计算机系统的基础组件。**

**核心要点：**
1. 哈希函数：键到索引的映射
2. 冲突处理：开放寻址或链地址
3. 负载因子：平衡性能和空间
4. 均摊分析：扩容均摊后仍为O(1)

**适用场景：**
- 需要快速查找
- 不需要有序
- 键值对存储
- 动态数据集

**不适用场景：**
- 需要范围查询
- 需要有序遍历
- 内存极其紧张
- 最坏情况要求严格
