# 23种设计模式

设计模式是一套被广泛接受和使用的解决特定问题的经验总结和最佳实践。根据设计模式的用途和实现方式，通常可以将设计模式分为三类：

1.创建型模式（Creational Patterns） 用于处理对象创建的机制，旨在通过控制对象的创建方式，帮助系统更加灵活地创建对象。创建型模式包括：工厂方法模式、抽象工厂模式、单例模式、建造者模式、原型模式等。

2.结构型模式（Structural Patterns） 处理类或对象的组合关系，旨在帮助系统更好地组织代码结构，实现高效的代码复用。结构型模式包括：适配器模式、桥接模式、装饰器模式、组合模式、外观模式、享元模式、代理模式等。

3.行为型模式（Behavioral Patterns） 处理对象之间的交互和职责分配，旨在帮助系统更好地组织代码行为，实现更加灵活和可扩展的系统。行为型模式包括：责任链模式、命令模式、解释器模式、迭代器模式、中介者模式、备忘录模式、观察者模式、状态模式、策略模式、模板方法模式、访问者模式等。





# 一、行为型模式

## 备忘录模式

备忘录模式（Memento Pattern）是一种行为型模式，它可以在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态，以便之后恢复对象到该状态。备忘录模式适用于以下情况：

1.需要保存和恢复对象的历史状态，以便支持撤销、恢复等操作。 

2.对象的状态变化比较复杂，且可能会涉及多个属性的变化，此时使用备忘录模式可以更加方便地保存和恢复状态。

3.在不破坏封装性的前提下，需要实现对象的状态保存和恢复。

备忘录模式通常与命令模式、编辑器等一起使用，用于支持撤销、恢复等操作。此外，在一些游戏、绘图等应用中，备忘录模式也可以用于保存和恢复场景、画布等的状态。

## 责任链模式

责任链模式（Chain of Responsibility Pattern）是一种行为型模式，它可以将多个对象组成一条链，按照顺序依次处理请求，并且可以动态地调整链中的顺序。责任链模式适用于以下情况：

1.需要动态组合处理对象，以便根据请求的不同，动态地调整对象的处理顺序和组合方式。 

2.需要在不显式指定接收者的情况下，让多个对象都有机会处理请求。 

3.需要避免请求发送者和接收者之间的耦合关系，以便更好地实现职责分离和可扩展性。

责任链模式通常用于处理请求的场景，比如 Web 应用中的过滤器、日志记录器等，以及一些工作流程中的流程节点。此外，责任链模式还可以用于实现异常处理、权限控制等功能。

## 状态模式

状态模式（State Pattern）是一种行为型模式，它可以让一个对象在不同状态下有不同的行为，从而使得对象的行为可以根据其状态动态地改变。状态模式适用于以下情况：

1.一个对象的行为随着其状态的改变而改变，并且在该对象的生命周期中状态转换比较频繁。 

2.需要将复杂的状态机逻辑分离出来，以便更好地实现状态转换和状态切换的逻辑。 

3.需要避免在一个类中出现过多的条件语句，以便更好地实现代码的可维护性和可扩展性。

状态模式通常用于解决对象的状态转换和状态切换的逻辑，比如订单状态、网络连接状态等。此外，在一些游戏、自动化控制等应用中，状态模式也可以用于实现状态机、有限状态机等。

## 策略模式

策略模式（Strategy Pattern）是一种行为型模式，它可以将算法家族封装起来，从而使它们之间可以相互替换，而不影响客户端的调用。策略模式适用于以下情况：

1.需要在不同的场景中使用不同的算法，比如排序、搜索等算法。 

2.需要在运行时动态地切换算法，以便根据不同的情况选择最优算法。 

3.需要避免使用大量的条件语句，以便提高代码的可维护性和可扩展性。

策略模式通常用于解决算法家族的封装和替换问题，比如排序算法、搜索算法等。此外，在一些业务逻辑较为复杂的应用中，策略模式也可以用于实现业务规则的封装和替换，以便更好地实现业务的灵活性和可扩展性。例如，计算器中的不同运算符就可以通过策略模式来实现。

## 模板方法模式

模板方法模式（Template Method Pattern）是一种行为型模式，它定义了一个操作中的算法骨架，而将一些步骤延迟到子类中实现。模板方法模式适用于以下情况：

1.需要在不同的场景中使用相同的算法，但各个步骤的具体实现可能不同。 

2.需要在运行时动态地确定算法的具体实现方式，以便根据不同的情况选择最优算法。 

3.需要避免在多个类中重复编写相同的代码，以便提高代码的可维护性和可扩展性。

模板方法模式通常用于解决相同算法的不同实现方式的问题，比如排序算法、搜索算法等。此外，在一些框架或库中，模板方法模式也可以用于实现抽象类或接口，以便让子类实现具体的行为。例如，在 Java 中，Servlet 中的 doGet() 和 doPost() 方法就可以通过模板方法模式来实现。

## 访问者模式

访问者模式（Visitor Pattern）是一种行为型模式，它可以将数据结构和数据操作分离开来，从而可以在不改变数据结构的前提下增加新的操作。访问者模式适用于以下情况：

1.需要对一个复杂的对象结构进行遍历，并对其中的元素进行不同的操作。 

2.需要在不改变对象结构的前提下，增加新的操作或算法。 

3.需要将数据操作从数据结构中分离出来，以便更好地实现可复用性和可维护性。

访问者模式通常用于解决对数据结构中的元素进行不同操作的问题，比如 XML 文件解析、编译器的语法分析等。此外，在一些需要增加新操作或算法的场景中，访问者模式也可以用于实现数据结构和操作的分离，以便更好地实现可复用性和可维护性。

## 观察者模式

观察者模式（Observer Pattern）是一种行为型模式，它定义了一种一对多的依赖关系，使得当一个对象状态发生改变时，它的所有依赖者都会收到通知并自动更新。观察者模式适用于以下情况：

1.当一个对象的状态发生改变时，需要让其他对象也随之做出响应，但不知道有多少个对象需要做出响应或者这些对象是谁。 

2.当一个对象需要将自己的状态通知给其他对象时，而又不想将这个操作硬编码到对象中，以便更好地实现可复用性和可维护性。

观察者模式通常用于解决一个对象状态改变需要通知多个对象的问题，比如 GUI 程序中的事件处理、消息通知等。此外，在一些需要对象之间松耦合的场景中，观察者模式也可以用于实现对象之间的通信，以便更好地实现可复用性和可维护性。

## 命令模式

命令模式（Command Pattern）是一种行为型模式，它将请求（命令）封装成一个对象，从而使得可以将请求与其它操作解耦。命令模式适用于以下情况：

1.需要将请求（命令）发送者和接收者解耦，从而让发送者和接收者不直接交互。 

2.需要支持撤销（Undo）操作、重做（Redo）操作或者事务（Transaction）操作，从而更好地实现可靠性和可恢复性。 

3.需要支持日志记录或者操作队列，从而更好地实现跟踪和监控。

命令模式通常用于解决请求发送者和接收者之间耦合度过高的问题，比如 GUI 程序中的菜单、工具条、按钮等。此外，在一些需要支持撤销、重做、事务等操作的场景中，命令模式也可以用于实现可靠性和可恢复性。同时，命令模式也可以与其他模式结合使用，比如与备忘录模式结合使用实现撤销操作、与观察者模式结合使用实现日志记录等。

## 中介者模式

中介者模式（Mediator Pattern）是一种行为型模式，它定义了一个中介者对象来封装一系列的对象交互。中介者模式使得各个对象之间不需要显式地相互引用，从而可以松耦合地进行交互。中介者模式适用于以下情况：

1.当一组对象之间存在复杂的相互关系时，可以通过引入中介者对象来简化这些关系。 

2.当一个对象会引起其他多个对象的行为变化时，可以通过引入中介者对象来避免对象之间的耦合度过高。 

3.当需要定制一个分布在多个类之间的行为时，可以通过引入中介者对象来集中这些行为。

中介者模式通常用于解决对象之间耦合度过高、复杂性过高的问题，比如 GUI 程序中的窗口、对话框等。此外，在一些需要定制分布在多个类之间的行为的场景中，中介者模式也可以用于实现行为的集中和定制。同时，中介者模式也可以与其他模式结合使用，比如与观察者模式结合使用实现对象之间的通信等。

## 解释器模式

解释器模式（Interpreter Pattern）是一种行为型模式，它定义了一种语言文法的表示，并定义了一种解释器来解释该语言中的表达式。解释器模式适用于以下情况：

1.当需要解释一种语言的语法规则时，可以使用解释器模式来表示该语法，并使用解释器来解释表达式。

 2.当需要对复杂的数据结构进行解释时，可以使用解释器模式来表示数据结构，并使用解释器来解释数据结构中的各个部分。

解释器模式通常用于处理复杂的语法解析、表达式计算、代码生成等问题。比如在编译器、解释器、正则表达式引擎等领域中，解释器模式都有广泛的应用。但是需要注意的是，解释器模式可能会导致代码变得复杂，并且可能会影响代码的性能，因此在使用解释器模式时需要谨慎。同时，解释器模式也可以与其他模式结合使用，比如与组合模式结合使用来表示语法树等。

## 迭代器模式

迭代器模式（Iterator Pattern）是一种行为型模式，它定义了一种顺序访问聚合对象中各个元素的方式，而又不暴露该对象的内部表示。迭代器模式适用于以下情况：

1.当需要遍历聚合对象中的元素时，可以使用迭代器模式来统一遍历接口，从而使遍历操作更加简便。 

2.当需要遍历多种不同类型的聚合对象时，可以使用迭代器模式来统一遍历接口，从而使遍历操作更加统一。

迭代器模式通常用于处理集合、列表、树等数据结构的遍历，从而避免暴露集合的内部结构。迭代器模式使得遍历聚合对象时可以避免使用硬编码方式，从而使得代码更加灵活、可扩展。同时，迭代器模式也可以与其他模式结合使用，比如与组合模式结合使用来遍历复杂的组合结构等。



# 二、结构型模式

## 适配器模式

适配器模式（Adapter Pattern）是一种结构型模式，它将一个类的接口转换成客户希望的另一个接口，从而使原本不兼容的类能够一起工作。适配器模式适用于以下情况：

1.当需要使用一个已经存在的类，但是它的接口不符合需求时，可以使用适配器模式来进行接口转换。 

2.当需要复用一些已经存在的类，但是它们的接口与系统的其他部分不兼容时，可以使用适配器模式来进行接口转换。

适配器模式常常用于整合不同的系统或者整合不同版本的类库，从而使它们能够协同工作。适配器模式可以使得系统的灵活性和可扩展性更高，因为系统可以在不修改原有代码的基础上，增加新的适配器类来支持新的接口。同时，适配器模式也可以与其他模式结合使用，比如与装饰器模式结合使用来增强适配器的功能等。

## 桥接模式

桥接模式（Bridge Pattern）是一种结构型模式，它将抽象部分与它的实现部分分离，从而使它们可以独立地变化。桥接模式适用于以下情况：

1.当需要实现一个抽象部分和它的实现部分之间的解耦时，可以使用桥接模式来实现。 

2.当需要在抽象部分和它的实现部分之间增加新的功能时，可以使用桥接模式来扩展。

桥接模式常常用于分层系统设计，其中底层实现细节可以被抽象出来，并与高层的抽象部分分离开来，从而使得系统更加灵活、可扩展。同时，桥接模式也可以使得实现部分的修改对客户端的影响最小化，从而提高系统的可维护性和可复用性。桥接模式与其他模式的结合也非常广泛，比如与工厂模式结合使用来创建桥接实例等。

## 装饰器模式

装饰器模式（Decorator Pattern）是一种结构型模式，它允许在不改变原有对象的基础上，动态地给一个对象添加一些额外的职责。装饰器模式适用于以下情况：

1.当需要在不影响其他对象的情况下，以动态、透明的方式给对象添加一些职责时，可以使用装饰器模式。 

2.当需要给一个对象添加多个不同的职责时，可以使用多个装饰器来实现。

装饰器模式的核心在于装饰器类的设计，它必须与被装饰的对象实现同样的接口，从而使得装饰器可以代替原有对象。装饰器模式可以避免使用继承来扩展对象功能的弊端，比如继承可能导致类的层次结构变得庞大、复杂，而装饰器模式则可以避免这种情况。同时，装饰器模式也非常灵活，可以动态地添加或者删除职责，从而使得系统更加灵活、可扩展。装饰器模式常常与其他模式结合使用，比如与工厂模式结合使用来创建装饰器实例。

## 组合模式

组合模式（Composite Pattern）是一种结构型模式，它允许我们将对象组合成树形结构来表示“整体-部分”层次结构。组合模式中的基本对象和组合对象具有相同的接口，这使得客户端可以以相同的方式对待它们。组合模式适用于以下情况：

1.当需要表示“整体-部分”层次结构时，可以使用组合模式。例如，当需要表示一棵树、一个文件夹、一个部门等层次结构时，可以使用组合模式来表示。 2.当需要对整个层次结构进行统一处理时，可以使用组合模式。例如，当需要对整个树、整个文件夹、整个部门等进行遍历、搜索、剪切、复制等操作时，可以使用组合模式来实现。

组合模式的核心在于组合类的设计，它允许我们将基本对象和组合对象以相同的方式进行处理。组合类中通常包含了一个子对象列表，用于存储组合对象中的子对象。组合类中还可以包含一些对子对象进行操作的方法，例如遍历子对象、添加子对象、删除子对象等。组合模式可以让我们使用相同的方式处理基本对象和组合对象，从而使代码更加简洁、易于理解和维护。

组合模式广泛应用于各种软件系统中，例如图形界面库、操作系统、游戏引擎等。组合模式在图形界面库中应用广泛，例如可以将图形对象组合成层次结构，从而实现复杂的图形界面。组合模式在游戏引擎中也应用广泛，例如可以将游戏对象组合成层次结构，从而实现复杂的游戏逻辑。组合模式是一种简单、实用的设计模式，它可以帮助我们实现更加灵活、高效、可维护的系统。

## 外观模式

外观模式（Facade Pattern）是一种结构型模式，它提供了一个统一的接口，用于访问子系统中的一组接口。外观模式隐藏了子系统的复杂性，简化了客户端与子系统之间的交互。客户端只需要通过外观接口访问子系统，而无需了解子系统的内部实现细节。外观模式适用于以下情况：

1.当系统中的一组接口需要被统一管理和访问时，可以使用外观模式。例如，当需要访问一个复杂的库或框架时，可以使用外观模式来简化对其的访问。 2.当需要对子系统进行封装时，可以使用外观模式。例如，当需要对一个复杂的系统进行封装，以便于后续的维护和升级时，可以使用外观模式来对其进行封装。

外观模式的核心在于外观类的设计，它提供了一个简单的接口，用于访问子系统中的一组接口。外观类可以根据客户端的需求，调用子系统中的不同接口，从而实现客户端的功能。外观模式可以使系统更加灵活和可维护，同时也可以提高系统的安全性和可靠性。外观模式还可以与其他模式结合使用，比如与单例模式结合使用来创建外观对象，或者与适配器模式结合使用来转换子系统的接口等。

外观模式广泛应用于各种软件系统中，例如操作系统、图形界面库、数据库访问接口、Web框架等。外观模式在Web开发中也很常见，例如使用MVC框架时，可以使用外观模式来封装数据库访问接口，从而简化开发过程。外观模式是一种简单、实用的设计模式，它可以帮助我们实现更加简洁、高效、可维护的系统。

## 享元模式

享元模式（Flyweight Pattern）是一种结构型模式，它旨在通过共享来有效地支持大量的细粒度对象。享元模式适用于以下情况：

1.当需要创建大量相似对象，并且创建这些对象的成本比维护它们的成本更高时，可以使用享元模式。 

2.当需要在一个应用程序中使用大量的对象时，可以使用享元模式来节省内存。

享元模式的核心在于共享，它通过共享对象来减少系统中的对象数量，从而降低内存占用。享元模式将对象分为内部状态和外部状态两部分，其中内部状态可以被共享，而外部状态则需要在对象之间分别存储。通过共享内部状态，系统可以有效地减少对象数量，从而提高系统的性能和效率。同时，享元模式也可以提高系统的可扩展性和可维护性，因为通过共享对象，可以将对象的状态集中在一个地方进行维护。

享元模式常常用于图形图像处理、文本编辑器、游戏开发等领域，因为这些应用程序通常需要大量的对象，而且这些对象的状态相对稳定，因此可以通过享元模式来节省内存。此外，享元模式也经常与其他模式结合使用，比如与工厂模式结合使用来创建享元对象等。

## 代理模式

代理模式（Proxy Pattern）是一种结构型模式，它允许在不改变原有对象的情况下，为其提供一个代理，以控制对原有对象的访问。代理模式适用于以下情况：

1.当需要控制对一个对象的访问时，可以使用代理模式。例如，当一个对象需要访问远程服务器上的资源时，可以使用代理来控制访问。 

2.当需要在访问一个对象之前或之后执行一些额外的操作时，可以使用代理模式。例如，当需要记录对象的访问日志时，可以使用代理来记录访问日志。

代理模式的核心在于代理类的设计，它实现了与原有对象相同的接口，并维护了一个对原有对象的引用。代理类可以在访问原有对象之前或之后执行一些额外的操作，从而对原有对象的访问进行控制。代理模式有多种形式，包括远程代理、虚拟代理、保护代理、缓存代理等，每种形式都有不同的应用场景。

代理模式常用于网络应用程序、分布式系统、远程对象访问等领域，因为这些应用程序需要通过代理来控制对远程对象的访问。此外，代理模式也可以用于优化性能、增强安全性、实现延迟加载等方面。代理模式与其他模式结合使用，比如与工厂模式结合使用来创建代理对象，或者与装饰器模式结合使用来增强代理对象的功能等。

# 三、创建型模式

 创建型模式通过封装对象的创建过程，提高系统的灵活性和可扩展性，减少对象创建的复杂度。以下是常见的创建型模式及其详细介绍： 

## 工厂方法模式

**工厂方法模式**（Factory Method Pattern）是一种创建型模式，它定义了一个用于创建对象的接口，但由子类决定要实例化的类是哪一个。工厂方法模式的核心思想是将对象的实例化过程延迟到子类中。

适用场景：

1. **客户端不需要知道具体类的创建过程**：需要通过接口或抽象类来生成具体的对象。
2. **产品类型较多，可能会新增类型**：需要在不修改现有代码的情况下扩展新产品。

优点：

- 提高系统的扩展性，新增产品时只需添加相应的工厂类。
- 客户端代码依赖于抽象类，而不是具体类，降低耦合性。

缺点：

- 增加系统的复杂性，每增加一个具体产品，就需要增加一个相应的工厂类。

## 抽象工厂模式

**抽象工厂模式**（Abstract Factory Pattern）是一种创建型模式，它提供一个接口，用于创建一系列相关或相互依赖的对象，而无需指定具体类。

适用场景：

1. **需要创建一组相互关联的对象**：比如 UI 组件中，按钮、文本框、复选框等风格统一。
2. **系统需要与多个产品族一起工作**：比如跨平台开发，需要不同的实现（Windows、Mac、Linux）。

优点：

- 易于更换产品系列，具体实现类对客户端是透明的。
- 符合开闭原则，可以通过新增产品族扩展系统。

缺点：

- 难以支持新增的产品等级结构，需要修改抽象工厂接口，影响所有实现类。

## 单例模式

**单例模式**（Singleton Pattern）是一种创建型模式，它确保一个类只有一个实例，并提供全局访问点。

适用场景：

1. **需要保证某个类只有一个实例**：如配置管理类、日志管理类、线程池等。
2. **需要提供全局访问点**：如共享资源或控制某些全局行为。

优点：

- 提供对唯一实例的受控访问，节省系统资源。
- 避免对象的重复创建和销毁。

缺点：

- 不支持继承，违背了单一职责原则。
- 可能带来隐式的全局状态，增加代码的复杂性。

## 建造者模式

**建造者模式**（Builder Pattern）是一种创建型模式，它将一个复杂对象的构建过程与表示分离，使得同样的构建过程可以创建不同的表示。

适用场景：

1. **对象的创建过程较复杂**：如需要多步骤或多个子对象组合。
2. **需要灵活地创建不同形式的对象**：如一个产品有多个版本。

优点：

- 将复杂对象的构建过程与具体表示分离。
- 代码易于维护，扩展性好。

缺点：

- 可能需要创建多个具体的建造者类，增加系统复杂性。
- 产品的内部变化会影响建造者类。

## 原型模式

**原型模式**（Prototype Pattern）是一种创建型模式，它通过复制现有对象来创建新对象，而不是通过实例化类。

适用场景：

1. **对象的创建成本较高**：如需要大量计算或复杂配置。
2. **需要保存对象的历史状态**：通过克隆对象来记录状态。

优点：

- 可以在运行时动态获取对象的状态。
- 克隆对象比重新初始化对象更高效。

缺点：

- 需要为每个类实现克隆方法，可能导致代码复杂。
- 深拷贝和浅拷贝的问题需要额外处理。

## 1. 单例模式

单例模式确保一个类只有一个实例，通常用于管理共享资源，如配置、缓存、线程池等。

**代码实现：双重检查锁**
 这是单例模式的标准写法，既保证线程安全，又避免性能损耗。

```java
public class Singleton {
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**JDK 中的应用：**

- `java.lang.Runtime.getRuntime()`
- `java.util.logging.Logger`

**Spring 中的应用：**
 Spring 的 `Bean` 默认是单例模式。可以通过 `@Scope("prototype")` 将其改为多例。

## 2. 工厂模式

工厂模式用于封装对象的创建逻辑，特别是当类实例化过程复杂时，可以降低耦合度。

**代码实现：简单工厂**
 以支付系统为例，不同支付方式需要不同的对象。

```java
public class PaymentFactory {
    public static Payment createPayment(String type) {
        switch (type) {
            case "AliPay":
                return new AliPay();
            case "WeChatPay":
                return new WeChatPay();
            default:
                throw new IllegalArgumentException("Unknown payment type");
        }
    }
}
```

**JDK 中的应用：**

- `java.util.Calendar.getInstance()`
- `javax.xml.parsers.DocumentBuilderFactory.newInstance()`

**Spring 中的应用：**

- `BeanFactory` 和 `ApplicationContext` 都是工厂模式的体现。

## 3. 策略模式

策略模式将不同算法封装为独立类，并允许在运行时选择不同的策略。

**代码实现：促销策略**
 以电商促销为例，支持满减、打折等多种策略。

```java
public interface PromotionStrategy {
    void applyPromotion();
}

public class DiscountStrategy implements PromotionStrategy {
    @Override
    public void applyPromotion() {
        System.out.println("Applying discount...");
    }
}

public class PromotionContext {
    private PromotionStrategy strategy;

    public PromotionContext(PromotionStrategy strategy) {
        this.strategy = strategy;
    }

    public void executePromotion() {
        strategy.applyPromotion();
    }
}
```

**JDK 中的应用：**

- `java.util.Comparator` 是典型的策略模式。

**Spring 中的应用：**

- 事务管理（`TransactionManager`），支持编程式和声明式事务。

## 4. 代理模式

代理模式通过代理对象控制对目标对象的访问，常用于权限控制、日志记录等场景。

**代码实现：静态代理**
 模拟对一个服务的权限控制。

```java
public interface Service {
    void execute();
}

public class RealService implements Service {
    @Override
    public void execute() {
        System.out.println("Executing real service...");
    }
}

public class ServiceProxy implements Service {
    private RealService realService;

    @Override
    public void execute() {
        System.out.println("Checking permissions...");
        if (realService == null) {
            realService = new RealService();
        }
        realService.execute();
    }
}
```

**JDK 中的应用：**

- 动态代理 `java.lang.reflect.Proxy`
- RMI（远程方法调用）

**Spring 中的应用：**

- AOP（面向切面编程）广泛使用代理模式。

## 5. 观察者模式

观察者模式定义一对多的依赖，当一个对象状态变化时，所有依赖它的对象都会收到通知。

**代码实现：事件通知**
 模拟微博用户的粉丝通知。

```java
public interface Observer {
    void update(String message);
}

public class User implements Observer {
    private String name;

    public User(String name) {
        this.name = name;
    }

    @Override
    public void update(String message) {
        System.out.println(name + " received message: " + message);
    }
}

public class Weibo {
    private List<Observer> observers = new ArrayList<>();

    public void follow(Observer observer) {
        observers.add(observer);
    }

    public void post(String message) {
        for (Observer observer : observers) {
            observer.update(message);
        }
    }
}
```

**JDK 中的应用：**

- `java.util.Observer` 和 `java.util.Observable`
- `javax.swing.event.ChangeListener`

**Spring 中的应用：**

- `ApplicationEvent` 和 `ApplicationListener` 是典型实现。

## 6. 装饰器模式

装饰器模式在不改变原始类的基础上，动态扩展其功能。

**代码实现：咖啡加料**
 模拟一个咖啡订单系统，可以动态加料。

```java
public interface Coffee {
    String getDescription();
    double getCost();
}

public class SimpleCoffee implements Coffee {
    @Override
    public String getDescription() {
        return "Simple Coffee";
    }

    @Override
    public double getCost() {
        return 5.0;
    }
}

public class MilkDecorator implements Coffee {
    private Coffee coffee;

    public MilkDecorator(Coffee coffee) {
        this.coffee = coffee;
    }

    @Override
    public String getDescription() {
        return coffee.getDescription() + ", Milk";
    }

    @Override
    public double getCost() {
        return coffee.getCost() + 1.5;
    }
}
```

**JDK 中的应用：**

- `java.io.BufferedInputStream` 和 `java.io.BufferedOutputStream`

**Spring 中的应用：**

- `BeanPostProcessor` 用于动态修改 Bean 的行为。

## 7. 模板方法模式

模板方法模式定义一个算法的骨架，把具体的实现留给子类。

**代码实现：任务执行模板**
 模拟定时任务的执行流程。

```java
public abstract class Task {
    public final void execute() {
        init();
        doWork();
        cleanup();
    }

    protected abstract void init();
    protected abstract void doWork();
    protected void cleanup() {
        System.out.println("Default cleanup...");
    }
}

public class DataProcessingTask extends Task {
    @Override
    protected void init() {
        System.out.println("Initializing data...");
    }

    @Override
    protected void doWork() {
        System.out.println("Processing data...");
    }
}
```

**JDK 中的应用：**

- `java.util.AbstractList` 和 `java.util.AbstractMap`

**Spring 中的应用：**

- `JdbcTemplate` 和 `RestTemplate`

## 8. 建造者模式

建造者模式用于创建复杂对象，特别是当对象有多个可选参数时。

**代码实现：构建 HTTP 请求**

```java
public class HttpRequest {
    private String method;
    private String url;
    private String body;

    private HttpRequest(Builder builder) {
        this.method = builder.method;
        this.url = builder.url;
        this.body = builder.body;
    }

    public static class Builder {
        private String method;
        private String url;
        private String body;

        public Builder method(String method) {
            this.method = method;
            return this;
        }

        public Builder url(String url) {
            this.url = url;
            return this;
        }

        public Builder body(String body) {
            this.body = body;
            return this;
        }

        public HttpRequest build() {
            return new HttpRequest(this);
        }
    }
}
```

**JDK 中的应用：**

- `StringBuilder`
- `Stream.Builder`

**Spring 中的应用：**

- `UriComponentsBuilder` 用于构建 URI。
