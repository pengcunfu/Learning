### 中介者模式（Mediator Pattern）

中介者模式（Mediator Pattern）是一种行为型设计模式，它用于减少对象之间的复杂交互。通常，当多个对象之间直接交互时，会导致系统耦合度增高，难以维护。而中介者模式通过引入一个中介者对象来管理这些对象之间的交互，使得各个对象之间不再直接交互，而是通过中介者进行沟通，从而降低了对象之间的依赖关系和耦合度。

### 1. 中介者模式的定义

中介者模式定义了一个中介对象（Mediator），用于封装一系列对象之间的交互。中介者使得对象不需要直接相互交互，而是通过中介者来协调行为。通过这种方式，降低了对象之间的耦合性，提高了系统的灵活性和可扩展性。

#### 主要角色：

1. **Mediator（中介者接口）**：定义了与各个 Colleague 对象交互的接口，通常是一个抽象类或接口。
2. **ConcreteMediator（具体中介者）**：实现 Mediator 接口，协调各个具体同事对象之间的交互。
3. **Colleague（同事类）**：每个 Colleague 类都知道它的中介者，并且通过中介者来进行通信。Colleague 类可以相互独立工作，但它们通过中介者进行协作。

### 3. 中介者模式的工作原理

中介者模式的核心思想是将各个对象之间的直接交互转移到一个中介者对象中。对象之间不再直接引用彼此，而是通过中介者来沟通。这有以下几个步骤：

1. **同事对象**：每个同事对象通常知道它的中介者对象，并通过中介者进行通信。
2. **中介者对象**：中介者对象负责接收同事对象的请求，并将请求传递给其他同事对象，管理对象之间的协作。
3. **消息传递**：同事对象通过中介者发送消息，避免了直接的相互依赖和紧耦合。

这种结构使得对象之间的耦合度降低了，任何对象的变更都不会直接影响到其他对象。通过这种模式，可以增加系统的灵活性和可扩展性。

### 4. 中介者模式的 Java 实现

假设我们在实现一个聊天室系统，其中多个用户通过中介者（聊天室）进行消息交流。每个用户是一个同事类，聊天室是一个中介者，它负责管理用户之间的消息传递。

#### 4.1. 定义中介者接口（Mediator）

```java
public interface ChatRoom {
    void sendMessage(String message, User user);
}
```

#### 4.2. 定义具体中介者（ConcreteMediator）

```java
import java.util.ArrayList;
import java.util.List;

public class ChatRoomImpl implements ChatRoom {
    private List<User> users;

    public ChatRoomImpl() {
        this.users = new ArrayList<>();
    }

    // 注册用户到聊天室
    public void addUser(User user) {
        users.add(user);
    }

    @Override
    public void sendMessage(String message, User user) {
        for (User u : users) {
            // 消息发送给除了自己以外的所有用户
            if (u != user) {
                u.receiveMessage(message);
            }
        }
    }
}
```

#### 4.3. 定义同事类（Colleague）

```java
public abstract class User {
    protected ChatRoom chatRoom;
    protected String name;

    public User(ChatRoom chatRoom, String name) {
        this.chatRoom = chatRoom;
        this.name = name;
    }

    public abstract void sendMessage(String message);
    public abstract void receiveMessage(String message);
}
```

#### 4.4. 定义具体同事类（ConcreteColleague）

```java
public class UserImpl extends User {

    public UserImpl(ChatRoom chatRoom, String name) {
        super(chatRoom, name);
    }

    @Override
    public void sendMessage(String message) {
        System.out.println(this.name + " sends message: " + message);
        chatRoom.sendMessage(message, this);
    }

    @Override
    public void receiveMessage(String message) {
        System.out.println(this.name + " received message: " + message);
    }
}
```

#### 4.5. 客户端代码（Client）

```java
public class Client {
    public static void main(String[] args) {
        // 创建聊天室（中介者）
        ChatRoom chatRoom = new ChatRoomImpl();

        // 创建用户并加入聊天室
        User user1 = new UserImpl(chatRoom, "User1");
        User user2 = new UserImpl(chatRoom, "User2");
        User user3 = new UserImpl(chatRoom, "User3");

        // 注册用户到聊天室
        ((ChatRoomImpl) chatRoom).addUser(user1);
        ((ChatRoomImpl) chatRoom).addUser(user2);
        ((ChatRoomImpl) chatRoom).addUser(user3);

        // 用户发送消息
        user1.sendMessage("Hello everyone!");
        user2.sendMessage("Hi User1!");
    }
}
```

#### 4.6. 输出

```
User1 sends message: Hello everyone!
User2 received message: Hello everyone!
User3 received message: Hello everyone!
User2 sends message: Hi User1!
User1 received message: Hi User1!
User3 received message: Hi User1!
```

在这个例子中，`User` 类是同事类，`ChatRoom` 是中介者接口，`ChatRoomImpl` 是具体中介者。每个 `User` 都通过 `chatRoom`（中介者）发送和接收消息。中介者会将消息传递给聊天室中的其他用户。

### 5. 中介者模式的应用场景

中介者模式适用于以下情况：

1. **多个对象之间存在复杂的交互关系**： 如果多个对象之间的交互变得非常复杂，并且彼此之间的依赖关系较强，可以使用中介者模式来集中管理对象间的通信，简化对象之间的耦合度。
2. **减少类之间的耦合**： 如果系统中的对象之间相互调用并造成了较高的耦合度，使用中介者模式可以将这些对象之间的依赖关系移到中介者类中，从而减少类之间的耦合性。
3. **管理对象之间的协作**： 如果系统中存在许多对象，它们需要相互协作并交换信息，可以使用中介者来统一管理协作的逻辑，而不是在每个对象中实现相同的逻辑。
4. **GUI 控件协作**： 中介者模式在图形用户界面（GUI）中的应用非常广泛。例如，在一个表单中，多个控件（如文本框、按钮、标签等）可能需要协作。中介者模式可以将这些控件的交互逻辑集中在一个中介者类中。
5. **分布式系统通信**： 在分布式系统中，多个服务之间的通信可能会变得非常复杂。可以通过中介者模式来管理服务之间的消息传递，避免服务之间直接的相互依赖。

### 6. 中介者模式的优缺点

#### 优点：

1. **减少了类之间的依赖关系**： 通过引入中介者来管理对象之间的交互，可以大大降低对象之间的耦合度。每个对象不再直接依赖其他对象，而是依赖于中介者。
2. **增强了灵活性和可扩展性**： 当需要添加新的对象或改变现有对象的交互逻辑时，只需要修改中介者，而不需要修改所有的同事类，从而增加了系统的灵活性和可扩展性。
3. **简化了对象的交互**： 在复杂的系统中，多个对象之间的交互可能会变得难以理解，使用中介者模式可以将这些交互集中管理，简化了对象之间的通信和协作。

#### 缺点：

1. **中介者可能变得复杂**： 如果系统中的对象数量很多，中介者可能会变得非常复杂，难以维护。所有对象的交互逻辑都会集中在一个中介者中，可能导致中介者成为系统中的一个单点故障。
2. **引入额外的类**： 中介者模式引入了中介者类和其他同事类，这可能会导致系统的类数量增加，增加了代码的复杂度。

### 总结

中介者模式通过引入一个中介者对象来管理多个对象之间的交互，减少了对象之间的耦合，提高了系统的灵活性和可扩展性。它适用于对象之间存在复杂交互的情况，尤其是在图形用户界面和分布式系统中。

```java
public class ConcreteMediator extends Mediator {
    private Alarm alarm;
    private CoffeePot coffeePot;
    private Calender calender;
    private Sprinkler sprinkler;

    public ConcreteMediator(Alarm alarm, CoffeePot coffeePot, Calender calender, Sprinkler sprinkler) {
        this.alarm = alarm;
        this.coffeePot = coffeePot;
        this.calender = calender;
        this.sprinkler = sprinkler;
    }

    @Override
    public void doEvent(String eventType) {
        switch (eventType) {
            case "alarm":
                doAlarmEvent();
                break;
            case "coffeePot":
                doCoffeePotEvent();
                break;
            case "calender":
                doCalenderEvent();
                break;
            default:
                doSprinklerEvent();
        }
    }

    public void doAlarmEvent() {
        alarm.doAlarm();
        coffeePot.doCoffeePot();
        calender.doCalender();
        sprinkler.doSprinkler();
    }

    public void doCoffeePotEvent() {
        // ...
    }

    public void doCalenderEvent() {
        // ...
    }

    public void doSprinklerEvent() {
        // ...
    }
}
```

```java
public class Client {
    public static void main(String[] args) {
        Alarm alarm = new Alarm();
        CoffeePot coffeePot = new CoffeePot();
        Calender calender = new Calender();
        Sprinkler sprinkler = new Sprinkler();
        Mediator mediator = new ConcreteMediator(alarm, coffeePot, calender, sprinkler);
        // 闹钟事件到达，调用中介者就可以操作相关对象
        alarm.onEvent(mediator);
    }
}
```
